## P0 详细计划

### P0-1 媒体库统计移出事件循环

状态：`[x] 已完成`

问题：

- `MediaLibraryStatsService.compute_stats()` 里直接调用 `os.scandir`、素材库扫描、账号/组目录扫描。
- 这些操作虽然在 async 函数中，但本质是同步磁盘 IO，会阻塞 qasync 事件循环。

实施内容：

- 将视频库、图片库全量扫描改为 `asyncio.to_thread(...)`。
- 将账号/账号组维度目录扫描抽出为纯同步 helper，并通过 `asyncio.to_thread(...)` 调用。
- 保留数据库查询仍在 async 上下文执行，避免 ORM 连接跨线程访问。

涉及文件：

- `src/services/material/media_library_stats_service.py`

验证方式：

- 已通过：`python -m pytest tests/unit/test_media_library_stats_service.py`。
- 后续建议在大素材库路径下记录刷新耗时和 UI 响应情况。

残余风险：

- 当前只是把同步 IO 移到后台线程，还没有做持久化索引；超大素材库仍会消耗总扫描时间，但不应再卡住 UI 事件循环。

## P1 详细计划

### P1-0 UI 优化总原则：视觉等价优先

状态：`[!] 强制执行约束`

背景：

- 账号管理页、待发布页、已发布页、媒体库页等高频页面已经形成固定视觉语言，包括 Fluent 表格底色、平台图标、状态徽章、标签胶囊、图标操作列、行高、列宽、表头、滚动条和右键/双击/选择行为。
- 性能优化和架构优化不能让用户感知为“页面换了一套样式”。如果必须改变可见 UI，必须先说明原因、影响范围、替代方案，并交由人工审核。

执行规则：

1. 默认不改变页面布局、控件外观、行高、列宽、颜色、图标、文案、右键菜单、双击/单击行为和筛选交互。
2. 新架构实现先作为并行候选组件存在，不直接替换默认入口。
3. 候选组件必须逐项复刻原视觉：平台图标、状态徽章、标签胶囊、操作图标、选中态、hover、表头、空值显示、tooltip、滚动和键盘行为。
4. 默认入口切换前必须完成至少三类验证：单元/编译测试、真实页面截图对比、人工确认。
5. 若某项性能优化无法做到视觉完全等价，需要先记录原因、收益、视觉差异和回退方案，等待审核后再改默认 UI。

适用页面：

- 账号管理页：保留原账号表视觉和交互；`AccountTableModel/AccountTableViewWidget` 仅作为候选实现，默认入口保持原 `account_table.AccountTableWidget`，直到视觉等价通过审核。
- 待发布页：发布队列表格仍需保持现有按钮、状态、底部任务面板联动和发布循环交互；`PublishRecordTableView` 只能在视觉等价完成后切默认。
- 已发布页：发布记录表格仍需保持现有行高、表头、操作列、右键菜单和筛选栏体验；Model/View 优化应优先在数据层、索引层、分页层完成。
- 媒体库页：后续优化必须保留原媒体库页面的卡片/列表/筛选/预览/操作视觉和交互，内部可迁移到 SQLite 索引、异步扫描、虚拟列表或 Model/View，但默认 UI 不得未经审核改变。

验收标准：

- 用户截图对比时，除非事先批准，不能出现“像换了一套表格/页面”的差异。
- 大数据量优化应主要体现为更快加载、更少卡顿、更低内存，而不是牺牲原 UI 风格。
- 所有视觉等价迁移都必须保留可快速回退到旧实现的入口。
