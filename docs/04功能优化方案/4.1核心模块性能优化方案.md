**文档简介**：本文档收录了系统核心模块在演进过程中为解决性能瓶颈、数据延迟、事件阻塞而实施的底层优化方案，旨在为后续的架构重构和性能提升提供参考基准。

---

## 1. 桌面端工作台数据流优化

**痛点背景**：  
早期的工作台数据强依赖同步拉取，且在底层服务（如后台任务、发布任务）通过事件总线触发 UI 更新时，常因为非主线程调度导致 Qt 渲染崩溃或界面卡死；此外，媒体库的扫盘统计算法会造成界面严重卡顿。

**优化方案**：  
1. **全局异步缓存隔离**：引入 `media_library_stats_cache` 服务，针对视频库与图片库的统计操作实行后端异步扫盘，将统计结果在内存中挂起，UI 端仅需读取缓存进行展示。
2. **事件总线主线程桥接**：对于 `PublishQueueExecutingCountChangedEvent` 及 `AccountUpdatedEvent` 等跨线程总线事件，统一通过 `QTimer.singleShot(0, callback)` 强行将执行栈跳跃回 Qt 所在的 `qasync` 主事件循环，彻底杜绝多线程渲染竞态。

## 2. 端云协同：设备心跳与短信调度同步机制

**痛点背景**：  
在多设备云控的场景下，原有的设备月活状态经常出现假死或不同步现象；当手机端执行挂断电话、上报短信发送状态等任务时，由于网络延迟与 `SMS_SEND_CNF` 和 `SMS_REPORT_IND` 信号混淆，云端极易丢失上报信息。

**优化方案**：  
1. **重构设备存活上报**：明确拨打电话等任务触发即刻视为活跃唤醒，不用等对端挂断才计数。避免“对方先挂断导致设备状态漏报”的逻辑死角。
2. **状态机与日志增强**：剥离单点数据库写入，采用本地持久化队列 + 云端云函数 `NoSQL` 后置批处理的方式缓冲大量的 SMS Report 和 Heartbeat 上报，保证即便在弱网环境下也能达成“最终一致性”。

## 3. Playwright 浏览器渲染性能与显示优化

**痛点背景**：  
在使用 Playwright 打开第三方平台时，由于框架内置的 `viewport` 限制和高分辨率 DPI 计算差异，常出现页面无法最大化、右侧截断留白、以及在 150% 缩放的笔记本屏幕上布局错乱的问题。

**优化方案**：  
遵循系统《Playwright 显示优化最佳实践》。放弃了传统的 `new_context()` 沙盒模式，全面拥抱 `launch_persistent_context`。在启动参数中显式关闭默认视口 (`viewport: None` / `no_viewport: True`) 并通过 `--start-maximized` 还原真实用户显示器的全屏渲染能力，大幅降低反爬被捕捉的几率。
