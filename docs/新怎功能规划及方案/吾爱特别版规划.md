# 吾爱破解 (52pojie) 特别版发布规划方案

## 1. 项目背景与目标
为了在“吾爱破解”论坛发布软件的福利版本，需要基于当前“媒小宝”完整版代码，快速构建一个专门的特别版。
*   **目标**：移除登录限制、移除账号等级限制（全功能解锁）、移除第三方商业连接（如飞书等）。
*   **核心原则**：不破坏主分支代码逻辑，支持一套代码同时编译出“完整版”和“特别版”。

## 2. 核心技术架构
采用 **“环境变量驱动的条件编译 + 运行时状态注入”** 方案。

### 2.1 环境变量定义
引入全局变量 `APP_DIST_MODE` 用于标识当前构建目标：
*   `STANDARD`: 标准完整版（默认）。
*   `52POJIE`: 吾爱破解特别版。

### 2.2 核心实现思路
1.  **身份伪造（绕过登录）**：在程序启动时，检测到 `52POJIE` 模式，则自动向内存注入一个“永久 VIP”用户状态。
2.  **功能屏蔽（精简程序）**：通过条件判断，在 UI 加载或服务初始化时跳过飞书、自动更新等模块。
3.  **权限解锁（全功能）**：由于 `CurrentUserService` 已被注入高级别权限，软件内所有基于权限的拦截逻辑将自动放行。

---

## 3. 详细实施细节

### 3.1 权限与登录 (Auth & Permission)
*   **涉及文件**：`src/services/auth/current_user_service.py`
*   **操作**：
    *   在 `main.py` 的 `run_app` 入口处，若为特别版模式，显式调用 `CurrentUserService().set_user()`。
    *   硬编码信息示例：`username="52pojie_Guest"`, `level="vip1"`, `is_expired=False`。
*   **核心修改**：**拦截所有 Auth 相关的 HTTP 请求**。在 `AuthService` 中增加逻辑，若是特别版则直接返回模拟的成功结果，不发起任何网络请求。

### 3.2 彻底去云端化 (Cloud Decoupling)
*   **接口拦截**：
    *   屏蔽所有指向 `api.wemedia.com` (示例域名) 的网络请求。
    *   在 `AsyncHttpClient` 或底层的 API 处理层增加全局过滤器，针对特别版模式直接拦截云端同步、数据备份请求。
*   **UI 链接清理**：
    *   全局搜索并移除所有跳转到官网、充值页面、购买咨询的外部链接。
    *   移除“检查更新”、“意见反馈（云端版）”、“云端备份”等菜单项。
*   **遥测与日志**：
    *   禁用 Sentry、日志上传或其他遥测插件，确保软件不会在后台偷偷联网上报数据。

### 3.3 界面定制 (UI Customization)
*   **涉及文件**：`src/ui/main_window.py`
*   **操作**：
    *   标题栏修改：由“媒小宝”改为“媒小宝 - 吾爱破解特别版 (离线增强版)”。
    *   侧边栏清理：移除“个人中心”、“我的会员”等需要联网展示的页面。
    *   状态栏修改：原本显示“已连接云端”的地方，改为显示“本地授权已激活”。

### 3.4 任务与数据 (Task & Data)
*   **本地化存储**：确保所有配置和任务记录仅存储在本地 SQLite 数据库中，不触发任何“云端同步成功”的提示逻辑。

---

## 4. 构建发布流程 (CI/CD)

通过构建脚本实现一键双发：

### 4.1 自动化打包脚本示例 (`scripts/build_dist.py`)
```python
# 打包标准版
os.environ["APP_DIST_MODE"] = "STANDARD"
subprocess.run(["pyinstaller", "main.spec"])

# 打包特别版
os.environ["APP_DIST_MODE"] = "52POJIE"
subprocess.run(["pyinstaller", "main.spec", "--name=WeMediaBaby_52pojie"])
```

## 6. 风险评估
*   **代码混淆**：即使是特别版，也建议进行适度的代码混淆，防止被二次恶意篡改。
*   **数据安全**：确保注入的伪造身份不会向云端发送真实的敏感请求，必要时切断云端同步逻辑。
