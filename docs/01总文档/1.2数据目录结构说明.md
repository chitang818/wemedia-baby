## 1. 设计原则

本项目采用 **"账号为中心（Account-Centric）"** 的数据存储结构。所有账号相关数据（浏览器持久化目录、指纹配置、明文 `cookies.json`、工作区文件等）均归档在 `{平台}/{账号目录}` 层级下，确保数据高内聚、易迁移、便于独立备份或清除。

---

## 2. 数据根目录

| 操作系统          | 数据根目录路径                                 |
| :---------------- | :--------------------------------------------- |
| **Windows** | `%LOCALAPPDATA%\WeMediaBaby\`                |

> 注意：Windows 统一使用 `LOCALAPPDATA`（本地非漫游），明确规避 `%APPDATA%`（Roaming）路径。

## 3. 目录树结构

```text
WeMediaBaby/
├── data/
│   ├── database.db                    # 账号数据库（SQLite）
│   ├── douyin/                        # 平台目录（如 douyin / kuaishou / wechat_video）
│   │   └── {profile_folder}/          # 账号目录（优先使用 UUID/不可变ID）
│   │       ├── cookies.json           # Cookie 明文 JSON（刷新登录/无头校验等业务唯一读取来源）
│   │       ├── browser/               # Playwright 侧目录（指纹、导出快照、Chromium user_data）
│   │       │   ├── user_data/         # Chromium 持久化目录（含 Default 等，真实登录态）
│   │       │   ├── storage_state.json # 关闭浏览器等时机导出的快照（备份/排障；启动时不从此灌 Cookie）
│   │       │   └── fingerprint_config.json  # 该账号绑定的浏览器指纹配置
│   │       ├── qt_profile/            # QtWebEngine 浏览器数据目录（混合模式使用）
│   │       │   └── cache/             # 渲染缓存
│   │       ├── workspace/             # 账号业务工作区
│   │       │   ├── media/             # 发布素材
│   │       │   │   ├── pending/       # 待发布
│   │       │   │   └── published/     # 已发布
│   │       │   ├── logs/              # 账号专属日志
│   │       │   └── temp/              # 临时文件
│   └── kuaishou/...
├── logs/                              # 全局日志目录
├── config/                            # 全局配置目录
├── cache/                             # 全局缓存目录
└── debug/                             # 诊断信息目录
    └── screenshots/                   # 发布失败时按平台保存的截图目录
```

## 4. 各目录/文件说明

| 路径/文件                               | 类型 | 说明                                                                                                                                                      |
| :-------------------------------------- | :--- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data/{platform}/`                    | 目录 | 平台根目录，如 `douyin`、`kuaishou`、`wechat_video`                                                                                                 |
| `data/{platform}/{profile_folder}/`   | 目录 | 账号根目录，优先使用 `profile_folder_name`（不可变 UUID），回退到 `platform_username`                                                                 |
| `.../cookies.json`                    | 文件 | 明文 Cookie 字典，**刷新登录状态、无头校验、发布前加载**等均只读此文件（由 `update_cookie` / 浏览器同步写入）                                     |
| `.../browser/user_data/`              | 目录 | Chromium 持久化目录（`launch_persistent_context` 的 `user_data_dir`），含 Cookie 库、LocalStorage 等。**删除会导致该 profile 浏览器内登录失效** |
| `.../browser/storage_state.json`      | 文件 | 关闭浏览器等时机由 `context.storage_state` 导出的快照，用于备份与排障；**启动浏览器时不再从此文件注入 Cookie**                                    |
| `.../browser/fingerprint_config.json` | 文件 | 该账号绑定的浏览器指纹配置（UA / Canvas噪声 / 屏幕参数等），确保同账号指纹一致性                                                                          |
| `.../qt_profile/`                     | 目录 | QtWebEngine 的持久化存储路径，仅在混合模式下使用                                                                                                          |
| `.../workspace/`                      | 目录 | 账号业务数据工作区（素材、日志、临时文件）                                                                                                                |
| `debug/screenshots/{platform}/`       | 目录 | 诊断截图目录，存放发布异常等场景的现场截图                                                                                                                |

## 5. 技术实现

### 5.1 路径管理器（`PathManager`）

**文件**：`src/infrastructure/common/path_manager.py`

所有路径生成统一通过 `PathManager` 类进行，**严禁在业务代码中手动拼接字符串路径**。

**主要 API：**

```python
from src.infrastructure.common.path_manager import PathManager

# 获取应用数据根目录
PathManager.get_app_data_dir()           # -> %LOCALAPPDATA%/WeMediaBaby/

# 获取数据库路径
PathManager.get_db_path()               # -> .../data/database.db

# 获取日志目录
PathManager.get_log_dir()               # -> .../logs/

# 获取诊断截图目录
PathManager.get_debug_screenshots_dir(platform="douyin")
# -> .../debug/screenshots/douyin/

# 获取账号数据目录（基础 API）
PathManager.get_platform_account_dir(
    platform="douyin",
    platform_username="media_expert_01",    # 仅用于报错/日志提示，严禁作为目录名
    profile_folder_name="profile_xxx",      # 必填项，强制规范为 profile_xxx
)
# -> .../data/douyin/profile_xxx/

# 获取账号数据目录（核心入口 API，推荐在业务中使用）
PathManager.get_account_root(account_dict)
# -> 优先解析 account_dict['profile_folder_name']，缺失时从 cookie_path 提取
```

> 上述 API **只返回路径，不会自动创建目录**，调用者需自行创建（通过 `AccountManagerAsync.add_account` 触发）。系统已全面弃用将 `platform_username` 用作回退目录的机制。

### 5.2 浏览器配置管理（`ProfileManager`）

**文件**：`src/infrastructure/browser/profile_manager.py`

- **职责**：基于 `platform` + `platform_username/profile_folder_name` 派生具体子路径（browser 目录、fingerprint 文件等）
- **主要方法**：
  - `get_user_data_dir()`：返回 Playwright `user_data_dir` 路径
  - `get_fingerprint()` / `save_fingerprint()`：读取或保存指纹配置

### 5.3 安全机制（Keyring）

部分加密能力使用的密钥通过系统级 **Keyring** 管理（见 `src/infrastructure/common/security/encryption.py`），不硬编码在仓库中：

| 项目             | 值                         |
| :--------------- | :------------------------- |
| 服务名称         | `WeMediaBaby`            |
| 用户名格式       | `key_{user_id}`          |
| Windows 存储位置 | Windows Credential Manager |

> 平台 Cookie 本身以 **`cookies.json` 明文** 落在账号目录；请勿把 Cookie 文件提交到版本库或外传。

### 5.4 缓存清理（`CacheManager`）

递归清理机制，覆盖以下路径（通过「设置 → 数据管理 → 清理缓存」触发）：

- 全局日志：`WeMediaBaby/logs/`
- QtWebEngine 缓存：`.../qt_profile/cache`、`Code Cache`、`GPUCache`
- 工作区临时文件：`.../workspace/temp/`
- 工作区日志：`.../workspace/logs/`

## 6. 开发规范

| 场景       | 规范                                                                                       |
| :--------- | :----------------------------------------------------------------------------------------- |
| 新建账号   | 使用 `AccountManagerAsync.add_account()`，自动调用 `PathManager` 创建标准目录结构      |
| 文件读写   | 始终使用 `PathManager.get_platform_account_dir()` 获取基准路径                           |
| 删除账号   | 删除数据库记录时，询问用户是否同步删除 `data/{platform}/{profile_folder}/` 物理文件      |
| 新功能开发 | **必须使用含 `platform` 参数的 API**，旧版仅含 `account_id` 的调用已被内部重定向 |
