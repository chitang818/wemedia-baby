## 1. 架构愿景与设计哲学

**媒小宝 (WeMediaBaby)** 是一款专为工作室与高频度创作者打造的"抗封禁、强扩展、极速热插拔"自媒体矩阵全自动化运营底座。

系统采用 **Community（社区开源版）** 与 **Pro（商业增强版）** 双轨制分发策略：
- **Community版**：开放抖音、快手核心插件，适合个人创作者入门
- **Pro版**：解锁全部10个平台插件、批量任务、数据中心、互动管理等商业功能

### 1.1 设计核心理念

1. **接口抽象化与控制反转 (IoC)**：系统的主控引擎逻辑严厉杜绝与任何特定流媒体平台（如抖音、小红书、视频号）产生直接的硬编码依赖。一切外部平台能力均通过底层的"标准插件协议能力抽象"实现反射挂载。通过 `ServiceLocator` 依赖注入容器统一管理服务生命周期。
2. **绝对物理级的沙盒工作流隔离**：在自动化执行层，针对不同定位、不同批次的账号群，提供完全互不污染且各自独立的浏览器内核沙箱（包含独立 Profile、Cookie 池以及本地存储），保障矩阵对抗联合风控检查探针的从容隐蔽。
3. **极简数据流式调度总线**：利用最严苛的异步状态机模型驱动 (MVVM/Signals)。UI 端作为纯被动接收器，坚决拒绝触发甚至涉足任何计算与超时挂起任务，一切长事务指令均向下交由全局事件环的守护服务统帅响应。
4. **Feature Flag特性开关机制**：通过 `config/feature_flags.py` 统一管控功能模块的启用与禁用，实现Community与Pro版的功能差异化配置。

## 3. 核心技术栈谱系

依托 Python 极其强悍的异步与网络底建生态，本项目最深层的运转脊骨依托如下强兵健将构建：

| 层级抽象 | 核心选型框架 | 技术深度与实战理由 |
| :--- | :--- | :--- |
| **GUI 展现层** | `PySide6` + `PySide6-Fluent-Widgets` | 极高水准的 Qt for Python 搭载原生级的现代化 Win 11 流畅语义组件渲染，带给专业级应用以极致性能体验。 |
| **异步集成网络** | `qasync` | 打破死板的 Qt 独立消息循环，实现底层 Python `asyncio` 事件环和前端渲染事件的完美无缝共享双绞线。 |
| **强一致性持久层** | `Tortoise ORM` + `aiosqlite` | 拥抱纯血统基于协程的架构，实现编译级强类型提示和优异的非阻塞并发 IO 控制。 |
| **大动脉网络通讯** | `aiohttp` + `urllib3` | 对海量图片预分配、全平台视屏资源并行分发推送等刚需进行极限资源掌控。 |
| **内核态虚拟指纹** | `Playwright` + `CDP双生协议` | 完全接管浏览器核心引擎。并用 DOM API 控制和极低位 CDP 链路协议截获。具备最高等级点击与网络请求穿透力。 |
| **持久化显示优化** | `launch_persistent_context` | 废除原生 `new_context`，以无视口(`no_viewport: True`)及原生最大化(`--start-maximized`)彻底解决界面被截断与DPI缩放问题，保障渲染一致性。 |
| **终极风控穿透** | `undetected-playwright` | 携手实现对于设备底层关键特征值（WebGL、AudioContext驱动特性）的魔改掩盖手段，对抗各大平台深海数据探测。 |
| **DI依赖注入** | `ServiceLocator` | 轻量级依赖注入容器，统一管理服务生命周期与依赖解析。 |
| **事件总线** | `EventBus` | 跨层异步消息传递，实现MVVM数据双向绑定与服务间解耦通信。 |
| **防解包编译墙** | `Nuitka` / `PyInstaller` | C++底端逻辑翻译，构筑核心代码及商业密钥的最强级符号层全防反编译加固。 |

### 3.1 GUI 表格批量更新约定（性能）

大量行一次性写入 `QTableWidget` / Fluent `TableWidget` 时，若在填充过程中反复触发排序、信号与重绘，容易造成主线程卡顿与界面闪烁。本项目约定：

1. **批量刷新三件套**：在填充前关闭 `setSortingEnabled(False)`、`setUpdatesEnabled(False)`，并视情况 `blockSignals(True)`；填充结束后按相反顺序恢复。
2. **参考实现**：[`src/ui/pages/publish/publish_records_page.py`](../../src/ui/pages/publish/publish_records_page.py) 中 `_refresh_table_impl` — 纯文本与操作按钮 **分两阶段** 填充，按钮列通过 `QTimer.singleShot` **分批** 创建（每批约 15 行），避免上千行时同步创建大量 `QWidget`。
3. **回收站列表**：[`publish_recycle_bin_page.py`](../../src/ui/pages/publish/publish_recycle_bin_page.py) 在 `_refresh_table` 中已使用上述批量保护。
4. **媒体库（视频/图片）**：[`video_library_page.py`](../../src/ui/pages/material/video_library_page.py)、[`image_library_page.py`](../../src/ui/pages/material/image_library_page.py) 的 `_populate_table` 在批量填充期间增加 `blockSignals`，与回收站策略一致。
5. **账号表**：[`account_table_view.py`](../../src/ui/pages/account/components/account_table_view.py) 使用 `QTableView + AccountTableModel + AccountTableDelegate`，避免逐行 `setCellWidget` 带来的大量 QWidget 和布局开销。
6. **进一步手段**：单表常规数据量在千行以上且仍明显掉帧时，再评估 `QAbstractItemView` 模型/视图分离或虚拟化方案，不作为默认复杂度。

用户提示类界面统一走 [`src/ui/utils/fluent_dialogs.py`](../../src/ui/utils/fluent_dialogs.py)（Fluent `MessageBoxBase` 系）；全局未捕获异常时优先 Fluent 错误框，`main.py` 中保留系统 `QMessageBox` 仅作兜底。

## 4. 底层硬核机制剖析

### 4.1 "鸭子类型" 的高阶组件级插件架构 (Plugins Protocol)

在 `src/plugins` 及商业扩展 `src/plugins/pro` 下沉集成的所有平台代码块逻辑：
- 底层强定义了 `AbstractLoginPlugin` 与 `AbstractPublishPlugin` 基础行为规约类。所有新平台扩展只需进行行为实现。
- 业务流和选择器的激进拆分：每个平台的 DOM 结构路径都被高度剥离提取存放于专属的字典表规则集 `selectors.py` 内。
- **动静解耦机制**：这让我们可以在后续应对大厂平台（比如头条、快手）那高频次的界面与埋点变换时，不破坏核心操作大树枝干即可动态甚至热切换这些定位字典完成升级响应。

### 4.2 智能微内核式的上下文池流淌 (Context Pool Pipeline)

自动化模块不再是一锤子买卖去简单启动和关闭某个进程对象。它是我们演化出的一套极为聪明的"状态复用态"后台调度总管：
1. **持久化私有 Profile**：项目将各商户各个独立自媒体号划定为了物理级别的用户数据本地存档沙盒。因此即使退出软件系统，也能享有长效期免授权或免扫码的复用续航收益。
2. **上下文热切换缓存**：面对在极短时间段内涌向相同目标视频平台的矩阵并发指令时，引擎能自主捕获可用通道，保留 Session（引擎会话）链接，极大降低机器资源的爆音负载与频发冷启动带来的二次人机鉴权挑战。

### 4.3 物理墙级的数据隔离切面 (Workspace Isolation Engine)

为了支持矩阵式多开规模环境首创的"应用内无缝微沙盒"功能区。
只要使用者利用鼠标在侧边栏一键切换了 Workspace 工作区场景，其背后：当前挂载的 `Database` SQLite游标探针、全局环境密钥实例乃至应用主事件环（EventLoop）底层数据堆栈对象都会瞬间全盘洗切换新隔离！彻底让同个设备下的多领域工作室彻底摆脱串号、IP代理数据流及身份数据泄露混淆的危局险境。

### 4.4 依赖注入与服务定位器 (DI Container & ServiceLocator)

系统通过 `src/infrastructure/common/di/` 模块实现轻量级依赖注入：
- **ServiceLocator**：全局服务注册与解析中心，统一管理所有服务的生命周期
- **懒加载机制**：服务按需实例化，避免启动时的资源浪费
- **接口隔离**：所有服务通过抽象接口注册，便于单元测试与Mock

### 4.5 管道过滤器模式 (Pipeline Pattern)

发布流程采用 `src/infrastructure/common/pipeline/` 中实现的管道模式：
- **PublishPipeline**：将发布流程拆分为多个独立的过滤器节点
- **链式处理**：每个过滤器负责单一职责（素材预处理→文本格式化→标签注入→平台适配）
- **可扩展性**：新增处理步骤只需实现过滤器接口并注册到管道中

## 5. 数据流转与运行生命周期

### 5.1 原生全链路自动化推送抽象流水线 (The Publish Pipeline)

1. **上层响应（View -> VM层）**：当用户在华丽的窗体中落键点击起初发布时。
2. **持久态建档落库（VM -> 服务中枢）**：将携带有多图文流/视频、复杂标签挂件与地理特性的包经过合法化校验，推入数据库落脚，打包转化为可被后续追踪的 `PublishTask` 领域实体任务。
3. **分配调度与发车编排**：由后台挂起的重镇引擎 `PublishManager` 解析包含的目标自媒体账号矩阵以及它们各自依附的网络环境要求。
4. **拉起潜行底层引擎**：基础设施层的特征工厂按环境安全分配法则唤起对应的无头浏览器或者可监控客户端进程（同时注入对应 IP 线路、脱机指纹证书组合）。
5. **插件组件挂载入位**：由工厂映射动态分配目标平台的特殊商业发布组件链环（例如：`src/plugins/pro/xiaohongshu/publish_plugin.py`），依次排队下放加载封皮资源、键入长文本逻辑处理等低等级指令流。
6. **落盘追猎与闭环流归口**：全流程中的关键步骤及异常点反馈回 `X-Ray` 日志拦截池中存储。一旦执行流达到末端，即发出一个闭环信号顺着全局 EventBus 回抛，最终引爆 VM 的状态变化重构 UI 的单元格呈现："渲染最终完工发牌灯箱状态"。
7. **发布列表队列节拍**：发布列表页「发布设置」将任务间隔（秒，默认 20）写入本地 `QSettings("WeMediaBaby", "PublishSettings")`。自动队列在每次 `publish_single` 执行结束且仍有下一待发布任务时，按设定值在 **[max(0, T−3), T+3]** 秒内均匀随机等待后再启动下一任务；最后一项完成后仅作短喘息，不追加长间隔。实现见 `src/ui/pages/publish/list_settings_dialog.py` 与 `publish_list_page.py`。

### 5.2 Pro版批量任务处理流程 (Batch Processing Pipeline)

1. **批量任务创建**：通过 `src/pro_features/batch/` 创建批量发布任务队列
2. **智能排期调度**：系统根据账号分组、平台类型、时间窗口自动编排任务执行顺序
3. **并发管道执行**：多账号并行发布，通过Pipeline模式保证流程一致性
4. **异常重试机制**：失败任务自动进入重试队列，支持指数退避策略

### 5.3 Pro版数据中心分析流程 (Data Center Pipeline)

1. **数据采集**：通过 `src/pro_features/data_center/` 采集各平台发布数据
2. **指标聚合**：播放量、点赞、评论、转发等核心指标的聚合分析
3. **可视化展示**：UI层图表组件渲染数据分析报告

### 5.4 Pro版互动管理流程 (Interaction Pipeline)

1. **评论管理**：通过 `src/pro_features/interaction/` 统一管理各平台评论
2. **私信处理**：跨平台私信的统一收发与自动回复
3. **敏感词过滤**：内置敏感词库，自动过滤违规内容

## 7. 系统级别安全与发售级防护

### 7.1 代码保护机制

依托全站归于唯一指定安全闭源库的宏观背景，应用为了阻击恶意的技术仿冒与算法抽取布置了立体高硬度防线：
1. **代码不可逆向性（底层硬阻断）**：交付至非特定终端机器的软件包环境将采用以 Nuitka 为底座进行的顶级硬链接翻译——代码会变成C++符号层，进行操作系统级执行调用，终结传统如 PyInstaller 打出的包极有可能遭受直接剥离解密被逆向获得 `.pyc` 原文的巨大悲剧。
2. **两套构建方案**：
   - **Nuitka构建**：生产级代码保护，编译为C++原生代码
   - **PyInstaller构建**：开发调试用快速打包

### 7.2 凭据与数据安全

1. **凭据管理**：部分敏感配置可依赖系统 **KeyRing** 管理密钥；各平台账号 Cookie 以本地 **`cookies.json` + 浏览器 `user_data`** 形式保存（详见 `docs/03分项功能介绍技术文档/3.4Cookie管理机制说明.md`）。
2. **RBAC权限控制**：基于角色的访问控制，Pro版用户享有更高级别的功能权限。
3. **凭证加密**：敏感数据（API Key、Token等）使用加密算法存储，防止明文泄露。
4. **数据目录隔离**：data目录不入库，仍需防止整机拷贝与文件外传。

---
> ⚠️ **开发协同军规提醒**：当需要进入 `src/plugins/pro/` 或触及任意核心组件树代码调整时，**极其严格地禁止** 调用任何脱离 `async`/`await` 同步阻塞方式的大幅磁盘 IO 或重型 HTTPS 请求代码，否则会导致高并发任务进程产生死锁和窗口雪崩断层；同时所有新增新媒体协议，必须坚决执行基架代码里所定的 `Interface` 范式抽象体系！Feature Flag开关的修改必须经过团队评审，禁止私自启用Pro版功能。
