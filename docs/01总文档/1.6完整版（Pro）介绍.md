# 媒小宝完整版（Pro / 52POJIE）介绍

> 本文档介绍**闭源完整版**的功能范围、分发方式、运行模式与与开源版的关系。  
> 对外开源仓库的 `README.md` 只描述开源版（OSS/Community），避免混淆与误用。

---


## 1. 三个发行模式（DistMode）

本项目支持 3 种发行模式（构建/分发维度），由 `APP_DIST_MODE` 控制，并可被打包脚本固化到 `config/dist_mode.json`：

- **OSS**：开源版（Community）
- **PRO**：闭源完整版（Pro）
- **52POJIE**：闭源离线特别版（面向特定渠道的“离线可用/全权限”变体）

> 说明：发行模式不等同于“账号授权状态”。发行模式决定“功能/入口是否存在”，账号体系决定“是否允许使用/额度限制”。

---

## 2. 完整版包含哪些能力

### 2.1 Pro 主要能力（示例）

- **批量任务**：批量视频任务、批量图文任务
- **媒体库**：视频/图片/文案管理与复用能力
- **带货推广**：购物车/团购等扩展能力（以版本为准）
- **数据中心**：数据统计与运营看板（以版本为准）
- **互动能力**：评论/私信等（以版本为准）
- **多平台能力**：除开源版平台外的其它平台插件（以版本为准）
- **高级调度**：更强的定时/重试/队列/断点续传等

### 2.2 媒小宝账号体系（闭源）

完整版包含“媒小宝账号体系”，通常涉及：

- 登录/注册/找回
- 个人中心（会员等级、到期时间、权益）
- 订阅/权限校验（额度、试用次数、发布拦截规则等）

## 3. 分发方式（推荐口径）

### 3.1 开源仓库（GitHub/Gitee）

- **公开仓库**只包含开源版源码（OSS/Community）
- 社区可基于开源仓库进行二次开发

### 3.2 完整版安装包（Releases）

- 在 GitHub/Gitee Releases 提供**编译后的安装包**（闭源二进制）
- 完整版可免费试用（以你的实际运营策略为准）
- 若你的运营策略是“注册登录 + 关注公众号获得全部权限”，请确保：
  - 客户端只保存必要的接口地址（不要把云端密钥打进客户端）
  - 权限判断在服务端为准，客户端仅做展示与基础拦截

## 4. 代码与仓库组织（与开源版的关系）

### 4.1 闭源代码存放

闭源核心逻辑建议放在（本地保留，不推送开源仓库）：

- `src/proprietary/`：账号登录、订阅权限、与账号强绑定的 UI 等

开源仓库中对应公共路径保留“包装/占位实现”，确保 OSS 在缺失闭源模块时不会崩溃。

### 4.2 Pro 功能页面与插件

若项目中存在以下目录（以你仓库实际为准）：

- `src/pro_features/`：Pro UI 页面/业务能力
- `src/plugins/pro/`：Pro 平台插件

是否对外开源由你的策略决定；但通常这些属于完整版能力的一部分。

## 5. 构建与打包（完整版）

### 5.1 推荐使用脚本

- 交互式入口：`scripts/build/build.bat`
- Fast（PyInstaller）：`scripts/build/build_fast.ps1`
- Secure（Nuitka）：`scripts/build/build_nuitka.ps1`

### 5.2 DistMode 示例

在 PowerShell 中：

```powershell
# PRO
.\scripts\build\build_nuitka.ps1 -DistMode PRO

# 52POJIE
.\scripts\build\build_nuitka.ps1 -DistMode 52POJIE
```

> 更多打包细节参考：`docs/01总文档/1.4软件打包实施方案.md`

---

## 6. 注意事项（强烈建议）

- **不要在客户端打包任何云端密钥**（只保留 base URL，密钥只在服务端）
- **版本边界要明确**：OSS 必须能在无账号体系时正常运行基础功能
- **产物命名要可区分**：安装包名里带上 `Fast/Secure + DistMode + 版本号`
