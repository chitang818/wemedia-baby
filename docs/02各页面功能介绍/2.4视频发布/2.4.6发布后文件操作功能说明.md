## 1. 功能概述

在发布列表页面执行发布任务，当某条任务**发布成功**后，系统可自动对该任务所使用的视频或图文文件执行指定的后置操作（移动或删除），以便用户通过文件夹结构直观区分哪些文件已发布、哪些尚未发布。

本功能仅对「发布成功」的任务生效，发布失败的任务不触发任何文件操作。

---

## 2. 功能入口与配置

### 2.1 配置入口

在**发布列表页面**顶部工具栏点击「发布设置」按钮，打开「发布设置」弹窗（`list_settings_dialog.py`），在弹窗底部新增「**发布后文件处理**」配置区。

### 2.2 配置选项

共三个互斥选项（单选），持久化到 `QSettings`：

| 选项值 | 显示名称 | 说明 |
|--------|----------|------|
| `none` | 不处理（默认） | 发布成功后不对文件做任何操作 |
| `move` | 移动至媒体库已发布目录 | 将文件移动至对应账号或账号组的「已发布」目录下的日期子文件夹 |
| `delete` | 删除原文件 | 将文件从原路径永久删除 |

**配置持久化 Key**：`publish_list/post_publish_file_action`，存储值为 `none` / `move` / `delete`。

## 3. 目标目录规则（移动模式）

### 3.1 基础目录结构

沿用项目现有媒体库目录约定（`MaterialLibraryManager` 管理）：

```
<媒小宝媒体库根目录>/
    账号库/
        <平台中文名>_<账号昵称>/     ← 个人账号目录
            视频/
                已发布/
                    <YYYYMMDD>/       ← 按发布日期自动创建
                未发布/
            图文/
                已发布/
                    <YYYYMMDD>/
                未发布/
        账号组_<组名>/               ← 账号组目录
            视频/
                已发布/
                    <YYYYMMDD>/
                未发布/
            图文/
                已发布/
                    <YYYYMMDD>/
                未发布/
```

### 3.2 日期文件夹规则

- 文件夹名称为**发布成功时的日期**，格式 `YYYYMMDD`，例如 `20260326`。
- 若当日文件夹已存在，直接在其中追加文件，不重新创建。
- 若移动目标路径存在**同名文件**，在文件名后追加 `_1`、`_2`…以此类推，避免覆盖。

### 3.3 移动目标路径决策逻辑

目标目录取决于该文件在**当前发布列表**中属于哪种共用情况（详见第 4 节）：

- **个人账号独立发布**：移动到 `账号库/<平台中文名>_<账号昵称>/视频或图文/已发布/<YYYYMMDD>/`
- **账号组共用文件**：移动到 `账号库/账号组_<组名>/视频或图文/已发布/<YYYYMMDD>/`

## 4. 核心判断逻辑：文件何时执行操作

### 4.1 问题背景

同一个发布列表中，可能存在**多个账号共用同一个视频文件**的情况。  
若每个账号发布完就立即挪走文件，后续账号的任务将因文件不存在而失败。  
因此，系统需要判断「同一个文件是否还被其他任务引用」，**等到引用该文件的所有相关任务都发布成功后，才执行一次文件操作**。

### 4.2 判断模型

系统在**每次发布队列启动时**（点击开始发布按钮），对当前发布列表中所有`待发布（pending）`任务做一次预分析，建立「文件引用分组表」：

**分组 Key** = `文件绝对路径` + `所属共用范围`（账号组 ID 或独立账号 ID）

分组规则如下：

1. 遍历所有待发布任务，取每条任务的 `file_path`（支持多文件逗号分隔，图文场景）和 `platform_account_id`（账号 ID）。
2. 通过账号 ID 查询该账号是否属于某个账号组（`group_id`）。
3. 按 `(file_path, 共用范围Key)` 分组：
   - 若同一账号组内有 ≥2 个账号使用完全相同的 `file_path`，则这些任务归为「**账号组共用**」分组，共用范围 Key = `group:账号组ID`。
   - 其余情况（包括账号有组但本列表中同组内只有它自己用这个文件），归为「**账号独立**」分组，共用范围 Key = `account:账号ID`。

### 4.3 文件操作触发时机

每条任务发布成功后，系统检查该任务所属「文件引用分组」：

- **分组内所有任务均已发布成功** → 立即执行文件操作（移动或删除）。
- **分组内还有任务未完成（pending / running / failed）** → 暂不操作，继续等待。

> 注意：若分组内某条任务发布失败，则该分组的文件**不执行**操作（因为存在发布失败，保留文件以便重试）。

### 4.4 场景示例

**前提**：抖音A、视频号A、快手A 属于「测试账号组A」；抖音B 无组。

#### 案例1：每个账号使用不同文件

| 任务 | 账号 | 文件 | 所属组 | 分组Key |
|------|------|------|--------|---------|
| 任务1 | 抖音A | A0001.mp4 | 测试账号组A | account:抖音A_ID（组内唯一使用该文件） |
| 任务2 | 视频号A | A0002.mp4 | 测试账号组A | account:视频号A_ID |
| 任务3 | 快手A | A0003.mp4 | 测试账号组A | account:快手A_ID |
| 任务4 | 抖音B | A0004.mp4 | 无 | account:抖音B_ID |
| 任务5 | 抖音A | A0005.mp4 | 测试账号组A | account:抖音A_ID（组内唯一） |

每条任务发布成功后**立即**对各自文件执行操作，分别移动到各自账号的已发布目录。

#### 案例2：账号组内多个账号共用同一文件

| 任务 | 账号 | 文件 | 所属组 | 分组Key |
|------|------|------|--------|---------|
| 任务1 | 抖音A | A0001.mp4 | 测试账号组A | group:测试账号组A_ID（同组内3个账号共用） |
| 任务2 | 视频号A | A0001.mp4 | 测试账号组A | group:测试账号组A_ID |
| 任务3 | 快手A | A0001.mp4 | 测试账号组A | group:测试账号组A_ID |
| 任务4 | 抖音B | A0004.mp4 | 无 | account:抖音B_ID |
| 任务5 | 抖音A | A0005.mp4 | 测试账号组A | account:抖音A_ID（组内唯一使用A0005） |

- **A0001.mp4**：等任务1、2、3 全部成功，才执行一次操作，移动到 `账号组_测试账号组A/视频/已发布/20260326/`（或删除）。
- **A0004.mp4**：任务4 成功后立即操作，移动到 `抖音_抖音B/视频/已发布/20260326/`（或删除）。
- **A0005.mp4**：任务5 成功后立即操作，移动到 `抖音_抖音A/视频/已发布/20260326/`（或删除）。

## 5. 图文多文件处理

发布任务的 `file_path` 字段可能包含多个文件路径（逗号分隔），例如图文任务同时包含多张图片。

- 移动模式：将 `file_path` 中**所有文件**逐一移动到目标目录的同一日期子文件夹中。
- 删除模式：将 `file_path` 中**所有文件**逐一删除。
- 每个文件独立处理，单个文件操作失败不影响其余文件，但需记录日志。

---

## 6. 媒体库未配置时的处理

若用户在「设置」中尚未配置媒体库存储路径（`MaterialLibraryManager.get_root_dir()` 返回 `None`）：

- **移动模式**：跳过移动操作，在发布日志中输出警告提示「未配置媒体库路径，发布后文件未移动」，不报错、不影响发布结果标记。
- **删除模式**：不受媒体库路径影响，直接删除原文件。

---

## 7. 文件不在媒体库目录下时的处理

用户手动添加到发布列表的文件，路径可能不在媒体库目录下（如桌面、其他硬盘）：

- **移动模式**：仍执行移动操作，在**对应账号或账号组的已发布日期目录**中新建当日子文件夹，将文件移入。即无论源文件在哪里，目标目录始终按「账号库」规则确定。
- **删除模式**：直接删除原路径文件。

## 8. 新模块设计要求

### 8.1 模块位置

新建独立模块：`src/infrastructure/common/post_publish_file_handler.py`

### 8.2 对外接口

```python
class PostPublishFileHandler:
    """发布后文件操作处理器"""

    @staticmethod
    def build_file_groups(pending_tasks: List[Dict]) -> Dict[str, Dict]:
        """
        在发布队列启动时调用，对所有 pending 任务预分析，
        建立文件引用分组表。
        返回结构：{
            group_key: {
                "file_path": str,
                "task_ids": List[int],
                "target_type": "account" | "group",
                "target_id": int,
                "target_name": str,
                "platform": str,
                "file_type": "video" | "image",
                "pending_task_ids": Set[int],  # 待完成的任务ID集合
            }
        }
        """

    @staticmethod
    async def on_task_success(
        task_id: int,
        file_groups: Dict[str, Dict],
        action: str,  # "move" | "delete" | "none"
        user_log: logging.Logger,
    ) -> None:
        """
        每条任务发布成功后调用。
        检查对应分组是否全部完成，若是则执行文件操作。
        """

    @staticmethod
    async def on_task_failed(
        task_id: int,
        file_groups: Dict[str, Dict],
    ) -> None:
        """
        任务发布失败时调用，更新分组的失败标记，
        确保失败分组不触发文件操作。
        """
```

在 `publish_list_page.py` 的 `_run_publish_loop` 方法中：

## 9. 日志输出要求

所有文件操作需通过 `publish.user_log` Logger 输出到发布日志框（与现有发布日志格式一致）：

- 移动成功：`[文件整理] ✅ 已将 A0001.mp4 移动至 账号组_测试账号组A/视频/已发布/20260326/`
- 删除成功：`[文件整理] ✅ 已删除 A0001.mp4`
- 等待中（分组未完成）：`[文件整理] ⏳ A0001.mp4 还有其他任务使用，暂不处理`
- 操作失败（异常）：`[文件整理] ⚠️ 文件操作失败（不影响发布结果）：<错误信息>`
- 未配置媒体库：`[文件整理] ⚠️ 未配置媒体库路径，跳过移动操作`

---

## 10. 注意事项

1. **文件操作异常不影响发布结果**：移动或删除失败时只记录警告日志，不修改已标记为 `success` 的任务状态。
2. **发布队列停止时的处理**：若队列中途被手动停止，剩余未完成分组的文件保持不动，日志提示「队列已停止，部分文件未整理」。
3. **重启后的一致性**：分组表仅在每次点击「开始发布」时重新计算，基于**当前发布列表的 pending 任务**；不跨越多次发布会话累计。
4. **账号组 ID 获取**：通过 `publish_record.platform_account_id` 关联 `Account` 表，再查 `AccountGroup` 获取 `group_id`。
