# 批量视频页面 — 任务创建逻辑说明

| 项目 | 内容 |
|------|------|
| **文档名称** | 批量视频页面 — 任务创建逻辑说明 |
| **文档版本** | v1.0.8 |
| **最后更新时间** | 2026-03-30 |
| **更新时软件版本** | 1.0.8（与当前主程序/安装包版本号一致；改版时请同步更新本行与「文档版本」） |

**文档简介**：本文档描述批量视频页面在不同账号选择情况下，视频如何加载、如何分配给账号、任务如何生成并写入发布列表。

---

## 一、核心概念速查

| 概念 | 说明 |
|------|------|
| 发布目标 | 用户在"账号选择"区域所选的账号或账号组，统称为发布目标 |
| 账号组 | 若干真实平台账号的集合，选择时以整组为单位，创建任务前系统会自动展开 |
| 账号展开 | 将账号组替换为其成员真实账号的过程，展开后跨组去重（同一账号仅保留一次） |
| 专属视频 | 从账号自身媒体库目录（视频/未发布）或账号组目录自动加载的视频，带有归属标记 |
| 共享视频 | 用户手动从本地文件导入的视频，无归属标记，可在无专属视频的账号间共享分配 |
| 时间槽 | 用户在"发布时间"区域配置的所有发布时间点列表，格式为"年-月-日 时:分" |
| 隔离分配 | 每个账号/账号组只使用属于自己的专属视频，账号之间视频互不交叉 |
| 全量复制 | 账号组内每个成员账号都获得该组全部视频（每个成员各发一遍） |
| 顺序块分配 | 无专属标记的共享视频在账号间按顺序依次取用，每个视频只分配给一个账号 |
| 任务指纹 | 由（平台、平台账号名、文件路径、发布时间）四元组构成的唯一标识，用于去重 |

## 二、视频来源与隔离标记机制

这是理解所有分配逻辑的基础。

### 2.1 视频的两种来源

```
视频来源
│
├── 自动加载（选择账号后系统自动拉取）
│   ├── 选择独立账号 → 从该账号的媒体库「视频/未发布」目录加载
│   └── 选择账号组   → 从该账号组的媒体库「视频/未发布」目录加载
│
└── 手动导入（用户主动操作）
    ├── 选择本地视频文件
    └── 选择本地文件夹（批量导入）
```

### 2.2 隔离标记

| 视频类型 | 打标方式 | 标记内容 |
|---------|---------|---------|
| 独立账号自动加载的视频 | 加载时自动打标 | `_assigned_account_id` = 该账号的ID |
| 账号组自动加载的视频 | 加载时自动打标 | `_group_id` = 该账号组的ID |
| 手动导入的视频 | 不打任何标记 | 无（作为共享视频） |

> **关键规则**：带有隔离标记的视频，只会分配给对应的账号或账号组成员，绝对不会越界分配给其他账号或其他组。

## 三、任务生成的总体流程

```
用户操作
   │
   ├─ 选择发布目标（账号 / 账号组）
   │      └─ 系统自动从各自媒体库目录加载视频，打上归属标记
   ├─ （可选）手动导入本地视频（作为无标记的共享视频）
   ├─ 配置发布时间槽
   └─ 点击"添加到发布列表"
          │
          ▼
   ① 展开账号组 → 每个组的成员账号携带所属组ID标记
          │
          ▼
   ② 按隔离标记分组匹配
       ├─ 带 _group_id 的视频  → 只给对应账号组的成员（全量复制）
       ├─ 带 _assigned_account_id 的视频 → 只给对应的那个账号（1对1）
       └─ 无标记的共享视频   → 在无专属视频的账号间顺序块分配
          │
          ▼
   ③ 为每对（账号 × 视频）绑定时间槽 → 生成任务列表
          │
          ▼
   ④ 去重预检（对比已有发布记录，过滤重复任务）
          │
          ▼
   ⑤ 批量写入发布列表（每条任务一条发布记录）
```

## 四、账号选择情况分类

```
账号选择结果
│
├── 情况一：选择 1 个账号（单账号）
│
├── 情况二：选择多个独立账号（纯多选账号，不含任何账号组）
│   ├── 子情况 A：多个账号属于同一平台
│   └── 子情况 B：多个账号跨不同平台
│
└── 情况三：选择中包含账号组
    ├── 子情况 A：选择 1 个账号组
    ├── 子情况 B：选择多个账号组
    └── 子情况 C：同时混选账号组与独立账号
```

## 五、各情况详细逻辑

### 情况一：选择 1 个账号

**触发条件**：用户仅选择了一个独立账号。

**视频加载**：系统自动从该账号的媒体库「视频/未发布」目录加载视频，每条视频打上该账号的 `_assigned_account_id`。

**分配规则**：

- 该账号使用自己目录中的全部视频（按文件名排序）。
- 第 1 个视频绑定第 1 个时间槽，第 2 个视频绑定第 2 个时间槽，以此类推。
- 视频数多于时间槽数时，多余的视频不被分配；时间槽数多于视频数时，多余时间槽不产生任务。

**任务数公式**：

```
任务数 = min(该账号目录视频数, 时间槽数)
```

**举例**：

```
账号A（抖音）目录视频：视频1、视频2、视频3
时间槽：8:00、12:00、18:00

分配结果：
  账号A：视频1 → 8:00，视频2 → 12:00，视频3 → 18:00
  共生成 3 条任务
```

---

### 情况二A：选择多个同平台账号

**触发条件**：用户多选了若干个独立账号，这些账号属于同一平台（如全部为抖音账号）。

**视频加载**：系统逐个账号独立加载各自目录的视频，每条视频打上对应账号的 `_assigned_account_id`。账号之间的视频完全隔离，不共享。

**分配规则**：

- 每个账号只使用自己目录中的视频，互不干扰。
- 各账号的视频按文件名排序，依次绑定时间槽。
- 某个账号目录为空时，该账号不产生任何任务（预览中显示"待配置"）。

**任务数公式**：

```
总任务数 = Σ min(账号X目录视频数, 时间槽数)  （对所有账号求和）
```

**举例**：

```
账号A（抖音）目录视频：视频A1、视频A2、视频A3
账号B（抖音）目录视频：视频B1、视频B2
账号C（抖音）目录视频：（空）
时间槽：8:00、12:00、18:00（共3个）

分配结果：
  账号A：视频A1 → 8:00，视频A2 → 12:00，视频A3 → 18:00（3条）
  账号B：视频B1 → 8:00，视频B2 → 12:00（2条，目录只有2个视频）
  账号C：无视频，不产生任务
  共生成 5 条任务
```

> 与旧版本的区别：旧版本将所有账号的视频合并为一个共享池，视频会跨账号混用。新版本每个账号各自的目录严格隔离，视频不会越界分配。

---

### 情况二B：选择多个不同平台账号

**触发条件**：用户多选了若干个独立账号，账号跨越不同平台（如抖音 + 快手 + 小红书等组合）。

**视频加载**：与情况二A 完全相同，逐个账号独立加载各自目录视频，打上各自的 `_assigned_account_id`。平台不同不影响隔离逻辑。

**分配规则**：与情况二A 完全相同，每个账号只用自己目录的视频。每条任务的平台字段来自该账号自身，发布时走对应平台的上传流程。

**举例**：

```
账号A（抖音）目录视频：视频A1、视频A2
账号B（快手）目录视频：视频B1、视频B2、视频B3
时间槽：8:00、18:00（共2个）

分配结果：
  抖音账号A：视频A1 → 8:00，视频A2 → 18:00（2条，走抖音发布流程）
  快手账号B：视频B1 → 8:00，视频B2 → 18:00（2条，走快手发布流程，视频B3超出时间槽数不分配）
  共生成 4 条任务
```

---

### 情况三A：选择 1 个账号组

**触发条件**：用户选择了一个账号组（不选任何独立账号）。

**视频加载**：系统从该账号组的媒体库「视频/未发布」目录加载视频（注意：是组级目录，不是成员账号各自的目录），每条视频打上该组的 `_group_id`。

**账号展开**：将账号组内所有成员展开为独立账号列表，按组内顺序排列。

**分配规则（全量复制）**：

- 组内每个成员账号都获得该组目录的全部视频。
- 第 1 个视频绑定第 1 个时间槽，第 2 个视频绑定第 2 个时间槽，以此类推。
- 若视频数多于时间槽数，超出部分循环使用时间槽（取模）。
- 组内成员账号可跨平台，每条任务携带该成员的真实平台信息。

**任务数公式**：

```
任务数 = 组内成员数 × 组目录视频总数
```

**举例**：

```
账号组"矩阵组"目录视频：视频1、视频2（共2个）
组内成员：抖音账号A、快手账号B、抖音账号C（3个成员）
时间槽：8:00、18:00

分配结果：
  抖音账号A：视频1 → 8:00，视频2 → 18:00
  快手账号B：视频1 → 8:00，视频2 → 18:00
  抖音账号C：视频1 → 8:00，视频2 → 18:00
  共生成 6 条任务（3 成员 × 2 视频）
```

---

### 情况三B：选择多个账号组

**触发条件**：用户选择了多个账号组（不选任何独立账号）。

**视频加载**：系统逐个账号组独立加载各自目录的视频，每条视频打上所属组的 `_group_id`。账号组之间的视频完全隔离，不共享。

**账号展开**：每个组分别展开其成员，各组成员携带所属组ID标记。跨组出现的同一账号，在该账号所属的第一个组中保留，后续组中去重跳过。

**分配规则（各组独立全量复制）**：

- 每个账号组只用自己目录的视频，组间完全隔离。
- 每组内的所有成员账号都获得该组目录的全部视频（全量复制）。
- 各组独立计算，最终任务合并。

**任务数公式**：

```
总任务数 = Σ（各组成员数 × 该组目录视频数）  （对所有组求和）
```

**举例**：

```
账号组1（3个成员）目录视频：视频A（共1个）
账号组2（1个成员）目录视频：视频B、视频C（共2个）
时间槽：8:00、18:00

分配结果：
  账号组1 的3个成员，各自发布视频A → 8:00（3条）
  账号组2 的1个成员，发布视频B → 8:00，视频C → 18:00（2条）
  共生成 5 条任务（3×1 + 1×2）
```

**有重叠成员时的跨组去重**：

```
账号组"主力组"：账号A、账号B（主力组目录视频：视频X）
账号组"混合组"：账号B、账号C（混合组目录视频：视频Y）
← 账号B 同时属于两个组

分配结果：
  主力组：账号A发布视频X，账号B发布视频X（账号B归属主力组，不重复计入混合组）
  混合组：账号C发布视频Y（账号B已在主力组中，跳过）
  共生成 3 条任务（2+1），账号B只发布主力组的视频
```

---

### 情况三C：混选账号组与独立账号

**触发条件**：用户同时选择了至少一个账号组和若干独立账号。

**视频加载**：
- 账号组部分：从各组目录加载视频，打上 `_group_id`。
- 独立账号部分：从各账号目录加载视频，打上 `_assigned_account_id`。
- 两部分视频各自独立，不合并。

**分配规则**：
- 账号组部分：与情况三B 相同，各组独立全量复制。
- 独立账号部分：与情况二A/B 相同，各账号使用自己的专属视频。
- 整体去重：若某独立账号同时也是某选中组的成员，该账号归属于第一次出现的组，独立账号部分跳过该账号。

**举例**：

```
账号组"抖音组"（成员：账号A、账号B）目录视频：视频P、视频Q
独立账号：快手账号C（目录视频：视频R）

分配结果：
  账号A：视频P → 8:00，视频Q → 18:00（来自抖音组）
  账号B：视频P → 8:00，视频Q → 18:00（来自抖音组）
  账号C：视频R → 8:00（来自账号C自己的目录）
  共生成 5 条任务（2×2 + 1×1）
```

## 六、手动导入视频的处理方式

用户通过"选择视频文件"或"选择文件夹"手动导入的视频，不带任何归属标记，视为共享视频。

**分配规则**：

- 若账号已有专属视频（自动加载的），则手动导入的共享视频不会再分配给该账号。
- 共享视频只分配给没有任何专属视频的账号，在这些账号间按顺序块分配（每个视频只给一个账号）。
- 若所有账号都已有专属视频，则手动导入的视频不会被分配（处于未使用状态）。

| 场景 | 手动导入视频的去向 |
|------|-----------------|
| 所有账号都有专属视频 | 不分配（搁置） |
| 部分账号无专属视频 | 在无专属视频的账号间顺序块分配 |
| 所有账号都无专属视频（纯手动导入场景） | 在所有账号间顺序块分配 |

## 七、各情况汇总对比表

| 情况 | 选择内容 | 视频来源 | 分配方式 | 任务数公式 |
|------|----------|---------|---------|-----------|
| 情况一 | 1 个独立账号 | 账号自身目录 | 隔离（仅用自己的视频） | min(账号视频数, 时间槽数) |
| 情况二A | 多个同平台独立账号 | 各账号各自目录 | 各账号隔离 | Σ min(账号X视频数, 时间槽数) |
| 情况二B | 多个跨平台独立账号 | 各账号各自目录 | 各账号隔离 | Σ min(账号X视频数, 时间槽数) |
| 情况三A | 1 个账号组 | 账号组目录 | 组内全量复制 | 成员数 × 组视频数 |
| 情况三B | 多个账号组 | 各组各自目录 | 各组独立全量复制，组间隔离 | Σ（各组成员数 × 该组视频数） |
| 情况三C | 账号组 + 独立账号混选 | 各目录分别加载 | 组部分全量复制，独立账号部分隔离 | 组任务数之和 + 独立账号任务数之和 |

## 八、时间槽绑定规则

无论哪种情况，时间槽的绑定规则均相同：

- 每个账号的第 1 个视频绑定第 1 个时间槽。
- 每个账号的第 2 个视频绑定第 2 个时间槽。
- 以此类推，若视频数超过时间槽数，超出部分循环取模使用时间槽。

**循环取模示例**：

```
时间槽：8:00、18:00（共2个）
某账号有 5 个视频：
  视频1 → 8:00（槽位 0）
  视频2 → 18:00（槽位 1）
  视频3 → 8:00（槽位 0，循环）
  视频4 → 18:00（槽位 1，循环）
  视频5 → 8:00（槽位 0，循环）
```

## 九、去重预检机制

在将任务写入发布列表之前，系统会执行去重预检：

- 每条任务通过「任务指纹」（平台 + 平台账号名 + 文件路径 + 发布时间）标识唯一性。
- 与发布列表中已有的记录对比，已存在相同指纹的任务会被跳过，不重复写入。
- 预览界面中，用户可以手动删除特定的预览行，被删除的任务在正式提交时同样不生成。

---

## 十、每条任务包含的信息

无论哪种情况，最终生成的每条任务均包含以下字段：

| 字段 | 来源 |
|------|------|
| 平台 | 来自账号自身的平台类型（如 douyin、kuaishou） |
| 平台账号名 | 来自账号的 platform_username 字段 |
| 平台账号ID | 来自账号的 id 字段 |
| 文件路径 | 来自视频文件的本地路径 |
| 文件类型 | 固定为 video（视频页面） |
| 标题 | 优先取视频自身标题，无则使用公共标题 |
| 描述 | 优先取视频自身描述，无则使用公共描述 |
| 标签 | 优先取视频自身标签，无则使用公共标签 |
| 封面路径 | 来自公共封面设置 |
| 发布时间 | 来自时间槽分配结果 |
| 位置信息 | 来自公共配置中的 POI 设置 |
| 隐私设置 | 来自公共配置，非视频号平台自动清除"原创"声明字段 |
