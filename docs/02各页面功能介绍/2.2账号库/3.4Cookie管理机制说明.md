## 1. 什么是 Cookie，在本项目中起什么作用

Cookie 是自媒体平台（抖音、快手、视频号等）用来识别"用户已登录"的凭证。用户在浏览器中登录平台后，平台会在浏览器中写入一组 Cookie（例如 `sessionid`、`sid_tt` 等键值对）。只要后续请求携带这些 Cookie，平台就认为"这是已登录用户"。

在媒小宝中，Cookie 有两个核心用途：

- **刷新登录状态**：通过 Cookie 向平台发送 HTTP 请求，判断账号是否仍在线
- **自动发布**：发布视频时，浏览器需要携带 Cookie 才能完成上传和提交

因此，Cookie 的正确写入和读取是整个软件运行的基础。

## 2. Cookie 存储在哪里

### 2.1 文件位置

每个平台账号的 Cookie 存储在该账号的数据目录下，路径规则为：

```
%LOCALAPPDATA%\WeMediaBaby\data\{平台}\{profile文件夹}\cookies.json
```

举例：

```
C:\Users\张三\AppData\Local\WeMediaBaby\data\douyin\profile_61c2ad70b05e\cookies.json
```

路径中的三个变量：

| 变量 | 含义 | 示例 |
|------|------|------|
| `{平台}` | 自媒体平台标识 | `douyin`、`kuaishou`、`wechat_video` |
| `{profile文件夹}` | 账号的唯一数据目录名 | `profile_61c2ad70b05e` |
| `cookies.json` | Cookie 文件（固定文件名） | — |

### 2.2 文件格式

`cookies.json` 是一个标准 JSON 文件，内容为键值对字典：

```json
{
  "sessionid": "abc123...",
  "sessionid_ss": "def456...",
  "sid_tt": "ghi789..."
}
```

可以直接用文本编辑器打开查看，不涉及任何加密。

### 2.3 与 profile_folder_name 的关系

每个平台账号在数据库中有一个 `profile_folder_name` 字段（如 `profile_61c2ad70b05e`），它决定了该账号在磁盘上的数据目录名。Cookie 文件、浏览器指纹数据、工作区文件等都存放在这个目录下。

如果数据库中的 `profile_folder_name` 缺失，软件会在读取 Cookie 前自动尝试修复（从磁盘发现并回填）。

## 3. Cookie 的写入流程

Cookie 的写入发生在以下场景：

### 3.1 添加账号时

用户通过"添加账号"在浏览器中完成平台登录后，软件从浏览器上下文提取 Cookie，调用 `save_cookie` 写入 `cookies.json`。

### 3.2 打开已有账号浏览器后（早期同步）

用户双击打开已有账号的浏览器时，软件会在启动后按配置 **`cookie_early_sync_intervals`** 在短时间内多次执行早期同步（默认约 2 秒间隔），将当前浏览器中的最新 Cookie 写回 `cookies.json`。这样即使用户较快关闭浏览器，也有较大概率已落盘。

### 3.3 关闭浏览器时

浏览器关闭前，软件会提取当前的 Cookie 并写回 `cookies.json`，确保最新状态被持久化。

### 3.4 静默更新

已有账号的浏览器打开后约 10 秒，软件会在后台静默检测登录状态并更新 Cookie 和账号昵称等信息。

### 写入流程图

```
用户操作（登录/打开浏览器/关闭浏览器）
    │
    ▼
AccountManagerAsync.update_cookie(account_id, cookie_dict)
    │
    ├── 从数据库查询账号信息（platform_username, platform, profile_folder_name）
    │
    ├── CookieManager.save_cookie(...)
    │       │
    │       ├── 构造路径：data/{platform}/{profile_folder_name}/cookies.json
    │       └── json.dump → 写入文件
    │
    ├── 更新数据库中的 cookie_path 字段
    └── 更新登录状态为 online
```

## 4. Cookie 的读取流程

Cookie 的读取发生在以下场景：

- 点击"刷新登录状态"按钮
- 发布任务执行前的在线校验
- 打开浏览器时注入 Cookie
- 发布流水线中加载账号 Cookie

### 4.1 统一入口

所有读取都通过同一个入口：

```
AccountManagerAsync.load_account_cookie(account_id)
```

该方法的内部流程：

```
load_account_cookie(account_id)
    │
    ├── 1. ensure_account_has_profile_folder(account_id)
    │       → 若 DB 中缺少 profile_folder_name，从磁盘自动发现并回填
    │
    ├── 2. 从数据库获取账号信息
    │
    └── 3. CookieManager.load_cookie(platform_username, platform, profile_folder_name)
            │
            └── 仅读取 data/{platform}/{profile_folder_name}/cookies.json
                    → 存在且为非空 JSON 对象则返回
                    → 否则返回 None，日志提示「请先双击打开浏览器并登录」
```

### 4.2 与 `storage_state.json`、持久化 `user_data` 的关系

| 项目 | 作用 |
|------|------|
| `cookies.json` | **业务唯一读取来源**（刷新登录、无头校验、发布前加载等） |
| `browser/user_data/` | Chromium 持久化目录；**双击打开浏览器**时登录态主要由这里承载 |
| `browser/storage_state.json` | 关闭浏览器等时机 **导出快照**（`save_state`），便于备份与排障；**不会**在启动时灌入上下文，也 **不会** 被 `load_cookie` 读取 |

若仅有 `user_data` 内登录态、尚未通过同步生成 `cookies.json`，会出现「浏览器里已登录，但刷新登录报 Cookie 不存在」——需等待早期同步或正常关闭浏览器，直到 `cookies.json` 被写入。

## 5. Cookie 的使用场景

### 5.1 刷新登录状态

```
用户点击"刷新登录状态"
    → load_account_cookie(account_id) 加载 Cookie
    → 将 Cookie 组装为 HTTP 请求头
    → 向平台 API 发送请求（如抖音的用户信息接口）
    → 根据响应判断：在线 / 离线
    → 更新数据库中的登录状态
```

### 5.2 自动发布

```
发布任务开始
    → load_account_cookie(account_id) 加载 Cookie
    → 校验 Cookie 有效性（发送 HTTP 请求确认在线）
    → 将 Cookie 注入 Playwright 浏览器上下文
    → 浏览器携带 Cookie 打开平台发布页面
    → 执行发布流程
```

### 5.3 打开浏览器（注入 Cookie）

```
用户双击"打开浏览器"
    → load_account_cookie(account_id) 加载 Cookie
    → 转换为 Playwright 格式的 Cookie 列表
    → 注入到浏览器上下文
    → 浏览器打开平台页面（已登录状态）
```

## 6. Cookie 不存在时的排查思路

当出现"Cookie 文件不存在"提示时，按以下顺序排查：

### 6.1 检查 profile_folder_name

在数据库中确认该账号是否有 `profile_folder_name` 字段。如果为空，说明账号数据目录未正确绑定。

解决方法：双击打开该账号的浏览器，完成登录后关闭，软件会自动创建数据目录并写入 Cookie。

### 6.2 检查磁盘文件

打开对应的数据目录，确认是否存在 **`cookies.json`**（账号根目录下）：

```
data/{platform}/{profile_folder_name}/cookies.json   ← 刷新/无头等业务依赖此文件
```

若不存在，但 `browser/user_data/` 已使用过，说明可能尚未触发写回 `cookies.json`（多打开浏览器数秒或正常关闭后再试）。若整个 profile 从未登录过，则需先完成平台登录。

### 6.3 常见原因总结

| 现象 | 原因 | 解决方法 |
|------|------|----------|
| 添加账号后立即刷新报不存在 | 账号添加时未完成登录 | 双击打开浏览器完成登录 |
| 打开浏览器后很快关闭，刷新报不存在 | 早期同步未来得及执行 | 打开浏览器后至少等待 3 秒再关闭 |
| 更换电脑后所有账号报不存在 | Cookie 是本地文件，不跨电脑 | 在新电脑上重新登录各平台 |

---

## 7. 核心规则总结

1. **Cookie 存储为明文 JSON**，不加密，不绑定任何媒小宝用户 ID
2. **文件名统一为 `cookies.json`**，位于每个账号的 profile 数据目录（与 `browser/` 同级）
3. **所有读取走统一入口** `load_account_cookie` → 只读 **`cookies.json`**
4. **所有写入走统一入口** `update_cookie`，写入后同步更新数据库 `cookie_path` 与登录状态
5. **本机数据共享**：无论登录哪个媒小宝账号，都能访问本机所有平台账号的 Cookie
