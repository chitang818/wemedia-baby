## 1. 概述

本文档描述账号管理页中「添加账号」的完整流程：用户选择平台后，**先在账号列表中创建一条占位账号（平台昵称为「待登录」）**，再打开浏览器供用户登录；**检测到登录后，用获取到的平台昵称与 Cookie 更新该占位账号**，不再弹出「添加新账号」控制弹窗。

## 2. 流程总览

```
用户点击「添加账号」
    ↓
弹出「选择平台」对话框（可选：配置指纹）
    ↓
确定平台（如 抖音 / 快手 / 视频号）
    ↓
【先占位】在账号列表中插入一条新账号
    - 平台：所选平台
    - 平台昵称：「待登录」
    - 登录状态：离线
    - profile_folder_name：profile_xxx（唯一）
    - Cookie：空
    ↓
刷新账号列表，用户立即看到新的一行
    ↓
【打开浏览器】启动 Playwright 浏览器，导航到该平台登录页（插件 login_url）
    - 不弹出「添加新账号」弹窗
    ↓
用户在浏览器中完成登录
    ↓
【后台检测】轮询插件 check_login_status(context)
    ↓
检测到已登录
    ↓
【更新占位】提取 Cookie + 平台昵称（插件 extract_user_info）
    → 更新刚才那条占位账号：平台昵称、Cookie、登录状态
    → 关闭浏览器
    → 刷新账号列表
    ↓
用户看到该行由「待登录」变为真实昵称，状态为在线
```

## 3. 步骤说明

### 3.1 用户选择平台

- 入口：账号管理页「+ 添加账号」按钮。
- 若未登录软件，先要求登录。
- 弹出平台选择对话框（如 `AddAccountDialog`），用户选择平台（抖音/快手/视频号等），可选配置浏览器指纹。
- 确定后得到 `platform`、`fingerprint_config` 等。

### 3.2 先占位：插入「待登录」账号

- 调用 `AccountManagerAsync.add_placeholder_account(platform)`：
  - 生成唯一 `profile_folder_name`（如 `profile_` + 12 位 hex）。
  - 在库中创建一条账号记录：
    - `platform` = 所选平台
    - `platform_username` = `"待登录"`（或带后缀保证唯一，如 `"待登录_profile_xxx"`，列表展示可简化为「待登录」）
    - `cookie_path` = 空
    - `profile_folder_name` = 上述生成值
  - 返回 `(account_id, profile_folder_name)`。
- 刷新账号列表，新行立即显示（平台 + 「待登录」+ 离线等）。

### 3.3 打开浏览器（不弹窗）

- 调用 `PlaywrightBrowserService.open_new_account_window(...)`，并传入：
  - `platform`、`fingerprint_config`
  - `profile_folder_name`：与占位账号一致
  - `existing_account_id`：占位账号的 ID
  - `on_login_detected_callback`：检测到登录时用于「更新该占位账号」的回调。
- 浏览器启动并导航到该平台登录页（来自插件的 `login_url`）。
- **不再**根据 `browser_launched` 显示「添加新账号」弹窗；用户只看到主界面与浏览器窗口。

### 3.4 后台检测登录

- 服务层 `_monitor_new_account_login` 轮询 `plugin.check_login_status(context)`。
- 检测到已登录后，调用 `handle_save_new_account`（或等价逻辑）：
  - 从 context 提取 Cookie。
  - 调用 `plugin.extract_user_info(context)` 获取平台昵称。
  - 因存在 `existing_account_id`，执行 **更新回调**，不执行「新增账号」回调。

### 3.5 更新占位账号

- 更新回调逻辑（在 View 或 Service 层）：
  - 调用 `AccountManagerAsync.update_account_after_login(account_id, nickname, cookie_data)`：
    - 更新该账号的 `platform_username` 为昵称；
    - 写入 Cookie（与现有 Cookie 存储方式一致）；
    - 可选：将登录状态置为在线、更新 `last_login_at`。
  - 触发账号列表刷新（如 `account_updated` 或 `_schedule_reload()`）。
- 随后关闭浏览器（优雅关闭或超时后强杀），流程结束。

### 3.6 未登录即关闭浏览器

- 若用户未完成登录就关闭浏览器，或监听超时：
  - 占位账号仍保留在列表中（平台 + 「待登录」+ 离线）。
  - 用户可删除该行，或通过后续迭代的「继续登录」等入口，用同一 `profile_folder_name` 再次打开浏览器完成登录并更新该条账号（具体以实现为准）。

## 4. 与旧流程的对比

| 项目 | 旧流程 | 新流程 |
|------|--------|--------|
| 弹窗 | 浏览器打开后弹出「添加新账号」对话框 | 无该弹窗 |
| 账号创建时机 | 检测到登录后才在库中新增一条账号 | 选择平台后立即新增一条占位账号 |
| 列表展示 | 登录成功后才出现新行 | 选择平台后即出现「待登录」行，登录成功后该行更新为真实昵称 |
| 手动保存/关闭浏览器 | 弹窗内按钮 | 无弹窗；关闭浏览器由自动逻辑或用户直接关窗处理 |

## 6. 名词说明

- **占位账号**：仅含平台、`profile_folder_name`、平台昵称「待登录」、无 Cookie 的账号记录，用于在列表中占一行，待用户登录后更新为真实昵称与 Cookie。
- **profile_folder_name**：账号数据目录名，如 `profile_abc123def456`，与浏览器 user_data 路径、Cookie 存储路径一致，占位与更新共用同一 profile。
