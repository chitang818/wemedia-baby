## 1. 功能概述

本项目防风控体系分为两个彼此独立、在同一发布链路中同时生效的层次：

- **浏览器层（环境级）**：在浏览器启动时一次性注入，让"浏览器/页面看不出是自动化"（指纹、stealth、启动参数）。详见《3.1 指纹浏览器功能说明》。
- **发布层（行为级）**：在每次发布任务执行过程中实时调用，让"操作节奏像真人"（延迟、步骤间间隔、拟人点击/输入、冷却）。**本文档重点介绍此层**。

```
发布请求 → 各平台插件 → 带指纹+stealth的Context/Page（浏览器层）
                                    ↓
                       步骤链 StepRunner（发布层）
                            ↓        ↑
                      anti_risk 延迟与拟人
```

两层结合效果：**环境免疫检测 + 行为节奏仿真**，形成"环境 + 行为"双重防风控。

## 2. 浏览器层（环境级）防风控

> 详见《3.1 指纹浏览器功能说明》。本节补充源码文件与浏览器层具体能力，便于对照。

### 2.1 浏览器层源码文件

| 文件 | 职责 |
| :--- | :--- |
| `src/infrastructure/browser/browser_manager.py` | **UndetectedBrowserManager**：启动持久化 Context、注入 stealth 脚本、应用启动参数；发布时 `publish_executor` 取得其 `context` 作为 Page 传给各平台插件 |
| `src/infrastructure/browser/profile_manager.py` | **ProfileManager**：按账号管理 `user_data_dir`；生成/加载指纹配置（UA、Screen、WebGL、Battery、Connection、Canvas 噪声种子等）|
| `src/resources/scripts/stealth/stealth.js` | **抗检测脚本模板**：页面加载前注入，伪造 `navigator.webdriver`、硬件/屏幕/WebGL/Navigator/权限等，降低自动化特征 |
| `src/infrastructure/browser/browser_factory.py` | **BrowserFactory**：当前固定返回 `UndetectedBrowserManager` 实例 |

### 2.2 浏览器层主要能力

| 能力 | 说明 |
| :--- | :--- |
| **启动参数** | `--disable-blink-features=AutomationControlled`、`--exclude-switches=enable-automation`、WebRTC 相关禁用等，去除自动化特征 |
| **指纹配置** | UA、Screen（分辨率/颜色深度）、WebGL（vendor/renderer）、硬件（核心数/内存）、Battery、Connection、Canvas/AudioContext 噪声种子；同账号指纹固定持久化 |
| **Stealth 脚本注入** | 读取 `stealth.js` 模板，将指纹占位符替换为当前账号值，通过 `context.add_init_script()` 注入；覆盖 webdriver、硬件、CDP、Headless 检测等 |
| **Context 选项** | `no_viewport=True`（不固定视口）、`user_agent`、`locale=zh-CN`、`timezone_id=Asia/Shanghai`、`ignore_https_errors` 等 |
| **账号隔离** | 每账号独立 `user_data_dir`（`browser/fingerprint_config.json`），多账号环境完全隔离 |

## 3. 发布层（行为级）防风控公共模块

**源码**：`src/infrastructure/anti_risk/`

发布层防风控遵循"**公共能力抽离 + 各平台只做检测与配置**"的设计原则：
- **公共层**（`anti_risk/`）：负责"怎么等、怎么节流、怎么仿人操作"，与平台无关，各平台复用
- **插件层**（各平台 `steps/`）：负责"哪里算风控、哪里算频繁"，检测到后调用公共层能力处理

### 3.1 延迟与节流（`delays.py`）

| 函数 | 说明 | 默认参数 |
| :--- | :--- | :--- |
| `random_delay(page, base_ms)` | 带 `speed_rate` 与随机抖动（±20%）的基础延迟，避免固定等待节奏 | `delay_jitter_ratio=0.2` |
| `step_interval(page)` | 步骤结束后调用，插入步骤间间隔（基准 0.5s + 随机 0~2.5s）| `step_interval_base_seconds=0.5` |
| `operation_delay(page)` | 单次操作（点击/输入/滚动）前调用，默认 0.5-3s 随机延迟 | `operation_delay_min_seconds=0.5` |
| `cooldown_before_retry(seconds)` | 检测到「操作频繁」后冷却等待 N 秒再重试，由平台配置传入秒数 | — |

所有延迟函数均受 `metadata["speed_rate"]` 倍率影响（最低 0.5，越大延迟越长）。

### 3.2 拟人行为（`human_like.py`）

对底层 `HumanBehavior` 类做了发布层封装，接收 `metadata` 和 `config` 参数，支持动态关闭：

| 函数 | 说明 | 底层调用 |
| :--- | :--- | :--- |
| `human_click(page, selector_or_locator)` | 可选 `operation_delay` → 可选鼠标随机漫游 → 元素安全区内随机坐标 + 贝塞尔移动后点击 | `HumanBehavior.click_in_bounds()` |
| `human_type_text(page, selector, text)` | 逐字符节奏输入，含打错字概率（默认 2%），未启用时退化为 `locator.fill()` | `HumanBehavior.type_text()` |
| `random_mouse_wander(page)` | 视口内随机两点间贝塞尔曲线移动（15-35步），模拟无目的鼠标移动 | `HumanBehavior.mouse_move()` |
| `optional_browse_before_action(page)` | 步骤前以 40% 概率触发轻微滚动或随机鼠标漂移 + 短暂停留，降低"直接定点操作"特征 | `HumanBehavior.scroll()` + `random_mouse_wander()` |

**启用/禁用控制：**
- `config["enable_human_like"] = False` 或 `metadata["anti_risk_human_like"] = False` → 所有拟人功能退化为最简操作
- `config["enable_mouse_wander"] = False` → 禁用鼠标漂移
- `config["enable_browse_before_action"] = False` → 禁用步骤前浏览
- `config["browse_probability"]` → 调整步骤前浏览触发概率（默认 0.4）

### 3.3 底层行为引擎（`human_behavior.py`）

`src/infrastructure/browser/human_behavior.py` 的 `HumanBehavior` 类是所有拟人行为的底层实现，提供：

| 方法 | 实现说明 |
| :--- | :--- |
| `mouse_move()` | 三次贝塞尔曲线鼠标移动（20-40步，每步添加 ±1px 微抖动）|
| `type_text()` | 逐字符输入，基础延迟 50-150ms，大写/数字/符号 ×1.5，2%概率打错字并 Backspace 修正 |
| `scroll()` | 分段平滑滚动（5-10步），每段随机停留 0.3-1.5s 模拟阅读 |
| `click_in_bounds()` | 元素边界内缩后随机选点，贝塞尔移动（18-35步）后按下/松开鼠标 |

## 4. 防风控配置

各平台配置通过 `config/platforms/{platform}.json` 的 `anti_risk` 块传入，在 `publish_plugin.py` 入口读取后注入 `metadata["anti_risk_config"]`，传递给各步骤。未提供时各函数使用内置默认参数正常运行。

**全量可配参数：**

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `enable_human_like` | bool | `true` | 拟人操作总开关（点击/输入）|
| `enable_mouse_wander` | bool | `true` | 是否启用鼠标随机漫游 |
| `enable_browse_before_action` | bool | `true` | 是否启用步骤前随机浏览 |
| `browse_probability` | float (0~1) | `0.4` | 步骤前浏览触发概率 |
| `delay_jitter_ratio` | float (0~0.5) | `0.2` | 延迟随机抖动范围（±20%）|
| `operation_delay_min_seconds` | float | `0.5` | 操作前最小延迟（秒）|
| `operation_delay_max_seconds` | float | `3.0` | 操作前最大延迟（秒）|
| `operation_delay_before_click` | bool | `true` | 拟人点击前是否先做操作延迟 |
| `operation_delay_before_type` | bool | `true` | 拟人输入前是否先做操作延迟 |
| `step_interval_base_seconds` | float | `0.5` | 步骤间基准间隔（秒）|
| `step_interval_jitter_seconds` | float | `2.5` | 步骤间随机额外等待（秒）|
| `type_mistake_probability` | float (0~1) | `0.02` | 拟人输入模拟打错字概率 |
| `cooldown_after_frequent_seconds` | int | — | 触发"操作频繁"后冷却等待时长（秒）|

## 5. 步骤链调用时机

发布步骤链（StepRunner + 各 Step）中防风控函数的建议调用时机：

| 时机 | 调用函数 | 说明 |
| :--- | :--- | :--- |
| **每步执行前** | `optional_browse_before_action()` | 以一定概率触发随机浏览，降低"开始就直接操作"特征 |
| **每步成功后** | `step_interval()` | 步骤间最小自然间隔，避免"一步结束立刻下一步" |
| **单次操作前** | `operation_delay()` | 点击/输入/滚动前 1-5s 随机等待，避免固定节奏 |
| **点击按钮时** | `human_click()` | 替代 `page.click()`，元素内随机坐标 + 贝塞尔轨迹 |
| **文本输入时** | `human_type_text()` | 替代 `page.fill()`，逐字符节奏输入 |
| **需要固定等待** | `random_delay(base_ms)` | 替代 `page.wait_for_timeout(base_ms)`，加入 ±20% 抖动 |
| **检测到「操作频繁」** | `cooldown_before_retry(平台配置秒数)` | 插件层识别文案/选择器后调用，冷却后触发重试 |

## 6. 插件对接职责划分

防风控分工遵循"**公共层负责能力，插件层负责检测**"：

| 职责 | 负责方 | 说明 |
| :--- | :--- | :--- |
| 随机延迟 / 步骤间隔 / 冷却逻辑 | **公共层** `anti_risk/` | 与平台无关，各平台直接调用，无需重新实现 |
| 同账号发布间隔 / 单日上限 | **Pipeline 层** | 放在发布 pipeline 的 filter 或调度逻辑里，与插件解耦 |
| 风控/账号异常的 DOM 检测 | **各平台插件** | 各平台弹窗文案、选择器不同，由插件自己的 `selectors.py` 实现 |
| "操作频繁"的检测 | **各平台插件** | 检测到后返回 `NeedsAction` 或调用 `cooldown_before_retry(配置秒数)` |
| 滑块/验证码检测 | **各平台插件** | 各平台 UI 不同；检测到后返回明确原因 + 建议 |

---

## 7. 异常处理与边缘兜底

| 场景 | 处理机制 |
| :--- | :--- |
| 检测到"操作频繁"弹窗/Toast | 调用 `cooldown_before_retry(seconds)` 冷却，返回 `NeedsAction(action="need_retry")` 触发重试 |
| 发布按钮点击失败 | 各平台 step_11 降级为普通 `.click()` 或 DOM `el.click()` 再次尝试 |
| 单步操作多次失败 | `RunnerConfig.max_step_retries=3`，超过后返回 `PublishResult(success=False)` |
| 拟人模块 import 失败 | 自动降级为最简操作（`locator.click()` / `locator.fill()`），不影响主流程 |
| 风控/账号异常弹窗 | 各平台插件检测到 `SECURITY.RISK_MODAL` 后返回失败并提示原因 |

## 8. 速率控制（`speed_rate`）

用户在 UI 中调整「发布速度」时，实际控制的是 `metadata["speed_rate"]` 的倍率，影响所有延迟函数的计算结果。

| speed_rate 值 | 效果 | 建议场景 |
| :--- | :--- | :--- |
| `0.5` | 所有延迟缩短至 50%（最快）| 测试验证，风控风险相对较高 |
| `1.0`（默认）| 标准延迟 | 正常账号日常发布 |
| `1.5` / `2.0` | 延迟放大 1.5/2 倍 | 账号处于降权状态或高风控期 |

`speed_rate` 不得低于 `0.5`（代码层已做硬底保护）。  
`metadata["anti_risk_human_like"] = False` 可单次关闭拟人行为（仅当前任务生效）。
