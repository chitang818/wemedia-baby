# 自动昵称提取技术文档

| 项目 | 内容 |
|------|------|

| **文档版本** | v1.4.3 |
| **最后更新时间** | 2026-06-04 |

**文档简介**：本文说明账号登录、打开已有账号浏览器、刷新登录状态时，软件如何提取或同步平台昵称。当前实现不再使用旧的 `旧账号页 Playwright 管理模块` 路径，统一以服务层和平台登录插件为准。

## 1. 当前入口

| 场景 | 当前入口 | 说明 |
|------|----------|------|
| 新增账号后检测到登录 | `src/services/browser/playwright_service.py::_monitor_until_login()` | 登录确认后先保存 Cookie 和在线状态，再调用 `_extract_nickname()` 尝试更新昵称。 |
| 打开已有账号并静默更新 | `PlaywrightBrowserService._monitor_existing_account_update()` | 先用 HTTP 快速校验真实登录态，在线时尝试从浏览器上下文更新 Cookie、昵称和状态。 |
| 手动/自动刷新登录状态 | `src/services/account/account_verifier.py::verify_accounts_batch()` | 普通平台加载本地 Cookie 后走 HTTP 校验；小红书走本地 Profile 同步分支。 |
| 小红书普通 Chrome 关闭后同步 | `src/services/account/xhs_profile_sync_service.py::XhsProfileSyncService.sync_account()` | 读取关闭后的 Chromium Cookie DB 与本地身份信息，不附加 Playwright。 |

## 2. 普通平台昵称提取流程

普通平台指抖音、快手、视频号等仍通过 `PlaywrightBrowserService` 打开 Playwright 持久化上下文的平台。流程如下：

1. 从数据库读取账号的 `platform`、`platform_username`、`profile_folder_name`。
2. 通过 `BrowserFactory` / `UndetectedBrowserManager` 打开账号独立 `user_data`。
3. 登录检测确认后，从浏览器上下文读取 Cookie 并写回账号库。
4. 调用 `PluginManager.get_login_plugin(platform)` 获取平台登录插件。
5. 优先执行 `plugin.extract_user_info(context)`，若返回 `LoginResult.nickname`，则更新 `platform_username`。
6. 如果插件 DOM 提取失败，但当前已有 Cookie，则调用 `verify_login_status()` 进行 HTTP 兜底，若返回 username，也可作为昵称来源。

关键代码位置：

- `src/services/browser/playwright_service.py`：浏览器生命周期、登录监控、昵称提取调度。
- `src/services/account/login_status_verifier.py`：统一 HTTP 登录状态校验入口。
- `src/plugins/**/login_plugin.py`：各平台 DOM/HTTP 登录态检测与用户信息提取。

## 3. 小红书昵称同步流程

小红书在当前版本采用更保守的普通 Chrome 登录维护模式：

1. 添加小红书账号时，`AddAccountDialog._should_skip_fingerprint_config()` 会跳过 Playwright 指纹配置。
2. 账号页通过 `DetachedChromeLauncher` 使用同一 `profile_folder_name` 打开普通 Chrome：`data/xiaohongshu/{profile_xxx}/browser/user_data`。
3. 用户在普通 Chrome 中完成登录或维护账号。
4. Chrome 关闭后，账号页的 watcher 调用 `XhsProfileSyncService.sync_account()`。
5. `ChromiumCookieReader` 复制并读取 Chromium Cookie 数据库，只按 `xiaohongshu.com` 域名过滤，并通过 Windows DPAPI/AES-GCM 尝试解密。
6. `XhsProfileIdentityReader` 从 LevelDB 文本片段中提取 nickname/user_id。
7. 读取到关键 session Cookie 后，写回账号 Cookie、在线状态和有效昵称。

小红书昵称过滤规则：

- 空字符串不写入。
- `小红书用户_...` 这类平台默认占位名不覆盖原昵称。
- 包含“登录”“创作服务平台”“http://”“https://”“{”“}”等明显非昵称文本时丢弃。
- 长度超过 40 的文本丢弃。

## 4. 刷新状态时的昵称来源

刷新登录状态不是专门的“改昵称”功能，但在校验成功时可能顺带更新昵称：

- 普通平台：`AccountVerifier` 加载 Cookie 后调用 `verify_login_status()`，若平台校验返回 username，可作为结果展示和后续状态依据。
- 小红书：刷新时优先走 `XhsProfileSyncService`，如果普通 Chrome Profile 正在运行，会返回 `profile_in_use=True`，不强制读取锁定中的 Cookie DB，也不误判账号离线。

## 5. 常见问题

**浏览器里明明已登录，为什么刷新仍显示 Cookie 不存在？**

普通平台需要 `cookies.json` 已经写回本地；可等待早期同步或正常关闭浏览器。小红书普通 Chrome 模式需要先关闭该账号 Chrome 窗口，软件才能读取本地 Profile。

**为什么小红书不在登录过程中实时提取昵称？**

当前小红书登录维护模式不附加 Playwright，因此软件不会在普通 Chrome 运行中实时监控 DOM；关闭窗口后再从本地 Profile 做同步，降低登录维护阶段的自动化痕迹。

**昵称提取失败会影响发布吗？**

昵称主要用于账号列表展示和账号匹配。发布更依赖账号 ID、平台、`profile_folder_name`、Cookie/持久化 Profile 和登录状态。昵称为空或未更新时，应优先检查登录态与 Cookie。

## 6. 维护清单

- 新增平台时，优先在对应 `login_plugin.py` 实现 `extract_user_info()` 与 `verify_cookie()`。
- 不要恢复旧的昵称目录规则，账号路径只能依赖 `profile_folder_name`。
- 小红书同步逻辑修改后同步更新 `test_xhs_login_verify.py`、`test_xhs_detached_chrome.py` 和 `test_add_account_dialog.py`。
- 若平台 DOM 变化导致插件提取失败，先更新平台登录插件，再补充对应单测或手动测试记录。
