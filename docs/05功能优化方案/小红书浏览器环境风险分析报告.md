# 小红书浏览器环境风险分析报告



## 结论摘要

小红书发布异常不适合继续用“同一账号发布不同作品”的方式归因。平台提示通常是账号级、延迟触发、聚合判断，不能可靠指出是哪次发布、哪个作品或哪个浏览器环境导致异常。

本项目当前已对小红书采用更保守策略：可见本机 Chrome、`strict_real_browser`、跳过 `stealth.js` 注入，并默认等待人工最终提交。但软件内 Chrome 仍然是由 Playwright 通过持久化上下文启动和控制，使用独立账号 profile，和用户日常本地 Chrome 不是同一个环境。

## 主要风险来源

| 风险项 | 普通本地 Chrome | 媒小宝 Chrome | 可优化性 | 代价 |
| --- | --- | --- | --- | --- |
| Playwright/CDP 控制痕迹 | 无 | 有 | 有限 | 只能降低行为异常，无法让其等同普通 Chrome |
| 独立 `user_data_dir` | 通常使用用户长期 profile | 每账号独立 profile | 可优化 | 需处理隐私、锁文件、并发和数据污染 |
| 登录环境突变 | 低 | 可能较高 | 可优化 | 需要账号冷却和稳定 profile 策略 |
| `launch_persistent_context` 启动 | 无 | 有 | 有限 | 是当前自动化基础能力 |
| `ignore_default_args` / sandbox 回退 | 无 | 可能有 | 可审计优化 | 某些机器可能启动失败 |
| 自动上传、填表、按钮探针 | 无 | 发布流程存在 | 可优化 | 需要更多人工确认点 |
| 风控提示后继续队列 | 无 | 已有停止逻辑，本次扩展关键词 | 已优化 | 可能增加任务中断次数 |

## 本次实现

- 新增小红书浏览器环境快照：采集 UA、UA-CH、webdriver、语言、时区、屏幕、WebGL、权限、可见风险提示、Cookie 名称等。
- 快照只记录 Cookie 名称、域名、路径和属性，不记录 Cookie 值。
- 小红书提交前安全模式会在等待人工提交前保存环境快照和发布按钮快照。
- 小红书失败诊断包新增 `xhs_environment_snapshot.json`，并在 `metadata.json` 中写入摘要。
- 小红书上传步骤会记录上传前、上传成功后的环境快照，形成提交前证据链。
- 扩展发布队列风险关键词，覆盖“脚本”“自动化”“AI 自动化”“验证码”等提示，触发后停止同账号后续任务。

## 使用建议

- 已被提示异常的账号不要用于根因实验，只做低频、纯手动观察。
- 小红书保持默认人工最终提交，不建议打开自动点击发布。
- 若诊断包中出现“脚本、自动化、环境异常、验证码”等风险提示，应暂停该账号自动发布。
- 后续如需评估“复用用户本地 Chrome profile”，必须单独设计隔离方案，避免污染用户日常浏览器数据。

## 诊断文件

小红书发布失败或人工提交等待超时后，诊断目录中重点查看：

- `metadata.json`：摘要信息。
- `xhs_environment_snapshot.json`：提交前浏览器环境快照。
- `xhs_publish_snapshot.json`：小红书发布按钮状态。
- `xhs_publish_probe.json`：发布按钮 Shadow DOM 探针结果。
- `platform_analysis.json`：结构化分析建议。
