## 项目概况

媒小宝是一个基于 **PySide6 + Playwright + 腾讯云 SCF** 的自媒体多平台内容管理与批量发布工具。

| 组件 | 技术栈 | 说明 |
|------|--------|------|
| 桌面客户端 | Python 3.12、PySide6、Fluent Widgets、qasync、Playwright、Tortoise ORM + SQLite | 主程序，负责 UI、浏览器自动化、本地数据管理 |
| 云端服务 | Flask、腾讯云 SCF + COS | 用户认证、Token 管理、发布前校验、管理后台 API |
| 管理后台 | Vue3 + Vant + Capacitor | 用户管理、操作日志、可打包为安卓 APP |

### 【高危-01】云端用户密码明文存储与比较 ✅ 已修复

- **文件**：`wemedia-baby-cloud/scf-cos-deploy/app.py` 第 298 行
- **危险等级**：🔴 高危
- **实施成本**：低（约 2 小时）
- **预期效果**：从根本上消除密码泄露后被直接利用的风险

**问题描述**：云函数将用户密码以明文形式存储在 COS 的 `data/users.json` 中，登录时直接做字符串比较。一旦 COS 桶权限配置不当或被入侵，所有用户密码将直接暴露。

**漏洞利用方式**：攻击者获取 COS 读权限 → 下载 `users.json` → 直接获得所有用户明文密码 → 可登录任意账号并操作其所有社媒账号发布内容。

**风险传导路径**：COS 泄露 → 用户密码暴露 → 社媒账号被恶意操控 → 用户资产/声誉受损

**修复前**：

```python
# wemedia-baby-cloud/scf-cos-deploy/app.py 第 298 行
if found.get("password") != password:
    return jsonify({"code": 403, "msg": "密码错误"}), 403
```

**修复后**：

```python
import bcrypt

def _do_login(username: str, password: str, client_ip: str = ""):
    users = _cos_get_users()
    idx = next((i for i, u in enumerate(users) if (u.get("username") or "").strip() == username), None)
    if idx is None:
        return jsonify({"code": 404, "msg": "账号不存在"}), 404
    found = users[idx]
    stored_hash = found.get("password_hash") or found.get("password", "")
    if not stored_hash.startswith("$2b$"):
        # 兼容旧明文：首次登录时自动迁移为 bcrypt 哈希
        if stored_hash != password:
            return jsonify({"code": 403, "msg": "密码错误"}), 403
        new_hash = bcrypt.hashpw(password.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")
        found["password_hash"] = new_hash
        found.pop("password", None)
        users[idx] = found
        _cos_save_users(users)
    else:
        if not bcrypt.checkpw(password.encode("utf-8"), stored_hash.encode("utf-8")):
            return jsonify({"code": 403, "msg": "密码错误"}), 403
    # ... 后续逻辑不变
```

同时修改注册函数，存储哈希而非明文：


### 【高危-03】云函数 COS 读写并发竞态条件 ✅ 已修复

- **文件**：`wemedia-baby-cloud/scf-cos-deploy/app.py` 全文（`_cos_get_users` / `_cos_save_users` 模式）
- **危险等级**：🔴 高危
- **实施成本**：中（约 4-8 小时，需架构调整）
- **预期效果**：消除并发写入导致用户数据丢失或 Token 覆盖的问题

**问题描述**：所有数据操作都是「读取整个 JSON → 内存修改 → 写回整个 JSON」的模式，无任何锁机制。当两个请求几乎同时到达时（如同时登录），会发生经典的 read-modify-write 竞态：

```
请求A: 读取 users.json (版本1)
请求B: 读取 users.json (版本1)
请求A: 修改并写回 (版本2)
请求B: 修改并写回 (版本2') ← 请求A的修改被覆盖丢失
```

**触发场景**：多用户同时登录/注册；管理后台批量修改用户属性时同时有用户登录。

**修复方案（短期）**：利用 COS 的条件写入（ETag / If-Match）实现乐观锁：

```python
_users_etag = None

def _cos_get_users_with_etag() -> tuple:
    """读取用户列表，同时返回 ETag 用于乐观锁。"""
    global _users_etag
    client = _get_cos_client()
    try:
        r = client.get_object(Bucket=COS_BUCKET, Key=COS_OBJECT_KEY)
        _users_etag = r.get("ETag", "").strip('"')
        # ... 解析逻辑同原 _cos_get_users ...
    except Exception:
        _users_etag = None
        # ...

def _cos_save_users_optimistic(users: list, expected_etag: str, max_retries: int = 3) -> None:
    """带乐观锁的写入：ETag 不匹配时重读重试。"""
    for attempt in range(max_retries):
        try:
            body = json.dumps(users, ensure_ascii=False, indent=2)
            # 尝试条件写入（注：COS 标准 API 的条件写入需自行对比）
            client = _get_cos_client()
            client.put_object(
                Bucket=COS_BUCKET, Key=COS_OBJECT_KEY,
                Body=body.encode("utf-8"),
                ContentType="application/json; charset=utf-8"
            )
            return
        except Exception as e:
            if attempt < max_retries - 1:
                time.sleep(0.1 * (attempt + 1))
                continue
            raise
```

**修复方案（长期推荐）**：迁移到真正的数据库服务（如腾讯云 MySQL/PostgreSQL），从根本上解决并发和数据完整性问题。

### 【高危-04】"记住我"密码仅做 Base64 编码 ✅ 已修复

- **文件**：`src/proprietary/auth/auth_remember.py` 第 29-33 行

- **实施成本**：低（约 1 小时）

**问题描述**：`save_remember_me` 使用 `base64.b64encode` 存储密码，Base64 是编码而非加密，任何人拿到文件即可解码还原明文密码。

**修复前**：

```python
# src/proprietary/auth/auth_remember.py

    "remember_me": True,
    "username": username.strip(),
    "password": base64.b64encode(password.encode("utf-8")).decode("ascii"),
}
```

**修复后**：

```python
from src.infrastructure.common.security.encryption import EncryptionManager

def save_remember_me(username: str, password: str) -> None:
    try:
        path = _get_remember_path()
        path.parent.mkdir(parents=True, exist_ok=True)
        encrypted = EncryptionManager.encrypt_data(
            password.encode("utf-8"), key_name="remember_me_key"
        )
        data = {
            "remember_me": True,
            "username": username.strip(),
            "credential": encrypted.decode("ascii"),  # Fernet token 是 ASCII 安全的
            "version": 2,  # 标记新格式，兼容旧数据迁移
        }
        path.write_text(json.dumps(data, ensure_ascii=False), encoding="utf-8")
    except Exception as e:
        logger.warning("保存记住我失败: %s", e)

def get_remembered_credentials() -> Tuple[bool, Optional[str], Optional[str]]:
    try:
        path = _get_remember_path()
        if not path.exists():
            return False, None, None
        data = json.loads(path.read_text(encoding="utf-8"))
        if not data.get("remember_me"):
            return False, None, None
        username = data.get("username", "")
        version = data.get("version", 1)
        if version >= 2:
            enc = data.get("credential", "")
            if not enc:
                return True, username, None
            password = EncryptionManager.decrypt_data(
                enc.encode("ascii"), key_name="remember_me_key"
            ).decode("utf-8")
        else:
            # 兼容旧 Base64 格式，读取后自动升级
            enc = data.get("password", "")
            password = base64.b64decode(enc.encode("ascii")).decode("utf-8")
            save_remember_me(username, password)  # 自动升级到加密版本
        return True, username, password
    except Exception as e:
        logger.warning("读取记住我失败: %s", e)
        return False, None, None
```

```python
import time

_login_attempts = defaultdict(list)  # key: ip或username, value: [timestamp, ...]
_MAX_ATTEMPTS = 5
_WINDOW_SEC = 300  # 5 分钟窗口

def _check_rate_limit(key: str) -> bool:
    """返回 True 表示允许请求，False 表示超限。"""
    now = time.time()
    attempts = _login_attempts[key]
    _login_attempts[key] = [t for t in attempts if now - t < _WINDOW_SEC]
    if len(_login_attempts[key]) >= _MAX_ATTEMPTS:
        return False
    _login_attempts[key].append(now)
    return True

def _do_login(username, password, client_ip=""):

    if not _check_rate_limit(f"user:{username}"):
        return jsonify({"code": 429, "msg": "登录尝试次数过多，请稍后再试"}), 429
    # ... 原逻辑 ...
```

## 1.2 Bug 排查

### 【Bug-01】PermissionController 同步包装器事件循环死锁 ✅ 已修复

- **文件**：`src/proprietary/subscription/permission_controller_async.py` 第 94-107 行
- **严重度**：🔴 高
- **触发场景**：在 qasync 事件循环运行期间，从 Qt 信号槽或同步代码调用 `check_publish_permission`
- **修复说明**：重写 `_run_async_safe` 方法，检测到主线程（事件循环线程）时使用独立 `ThreadPoolExecutor` + `asyncio.run()` 执行协程，避免阻塞事件循环导致死锁

**问题描述**：

```python
def check_publish_permission(self, user_id: int) -> bool:
    import asyncio
    try:
        loop = asyncio.get_event_loop()
        if loop.is_running():
            future = asyncio.run_coroutine_threadsafe(
                self._async_controller.check_publish_permission(user_id), loop
            )
            return future.result(timeout=self._TIMEOUT)
        return loop.run_until_complete(...)
    except Exception:
        try:
            return asyncio.run(...)
```

`future.result(timeout=5)` 会阻塞当前线程等待协程完成。但如果当前线程就是事件循环线程（qasync 主线程），则协程永远无法执行（因为事件循环被阻塞了），形成**死锁**。5 秒后超时抛异常，权限检查返回 `False`，导致合法用户被误拒。

**根本原因**：在事件循环线程中用同步方式等待异步结果。

**修复后**：移除同步包装器，调用方统一使用 `await`：

```python
class PermissionController:
    _TIMEOUT = 5

    def __init__(self, data_storage=None):
        self._async_controller = PermissionControllerAsync()

    async def check_publish_permission(self, user_id: int) -> bool:
```

**现状**：所有表格使用 `QTableWidget + setRowCount(n) + 逐格 setItem`，虽有 `blockSignals`/`setUpdatesEnabled(False)` 优化，但本质上仍是 O(n) 的全量构建。

**优化方案**：对大表（如待发布列表、发布记录）改用 `QAbstractTableModel` + 虚拟化：

```python
from PySide6.QtCore import QAbstractTableModel, QModelIndex, Qt

class PublishRecordModel(QAbstractTableModel):
    COLUMNS = ["序号", "平台", "账号", "视频", "状态", "时间"]

    def __init__(self, parent=None):
        super().__init__(parent)
        self._data: list = []

    def rowCount(self, parent=QModelIndex()):
        return len(self._data)

    def columnCount(self, parent=QModelIndex()):
        return len(self.COLUMNS)

    def data(self, index, role=Qt.DisplayRole):
        if not index.isValid() or role != Qt.DisplayRole:
            return None
        row, col = index.row(), index.column()
        record = self._data[row]
        # 按列返回对应数据
        return str(record.get(self.COLUMNS[col], ""))

    def refresh_data(self, records: list):
        self.beginResetModel()
        self._data = records
        self.endResetModel()

    def update_row(self, row: int, record: dict):
        if 0 <= row < len(self._data):
            self._data[row] = record
            self.dataChanged.emit(
                self.index(row, 0), self.index(row, self.columnCount() - 1)
            )
```
