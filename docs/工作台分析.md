**
启动加载链路**

当前链路是：

**main.py** -> **run_desktop_runtime()** -> **MainWindow()** -> **_setup_navigation()** -> 立即创建 **workspace_page** -> **WorkspacePage.__init__()** -> **_setup_content()** -> 立即触发 **_refresh_data()** 和 **_refresh_media_stats_async()** -> **window.show()** -> **WorkspacePage.showEvent()**。

关键代码位置：

* **main_window.py (line 1060)**：工作台页面启动时立即创建。
* **workspace_page.py (line 130)**：一次性构建完整工作台 UI。
* **workspace_page.py (line 306)**：构建完 UI 后立即拉工作台数据和媒体库统计。
* **workspace_page.py (line 417)**：首次显示时又调度刷新。
* **base_page.py (line 183)**：首次 show 会 **setUpdatesEnabled(False)**，再用 10ms timer 解冻并淡入。

**空白 1-2 秒的主要原因**

最可疑的根因不是“工作台 UI 没创建”，而是“工作台已创建但首次绘制被 BasePage 冻结，解冻 timer 被启动期任务延迟”。

启动时中央区域空白，对应 **BasePage.showEvent()** 里的首次显示冻结逻辑。正常 10ms 后应该解冻，但此时 qasync 事件循环刚开始接管，已经排了这些任务：

* **WorkspacePage._refresh_data()**：调用 **DashboardService.get_dashboard_data()**。
* **DashboardService.get_dashboard_data()** 是串行执行账号统计、发布统计、任务统计、最近发布提醒。
* **dashboard_service.py (line 86)** 当前发布统计会 **find_records(limit=10000)** 拉取大量发布记录，再在 Python 层过滤、按日聚合、算成功率。
* **publish_record_repository_async.py (line 288)** **find_records()** 还会附加账号组名，这对工作台统计并不需要。
* **get_online_account_publish_reminders()** 又再次 **get_accounts()**，账号查询重复。
* **workspace_page.py (line 342)** 媒体库统计也在首屏触发，可能扫描/读取媒体库缓存，虽然大量工作用了 **to_thread**，但仍会占启动期 IO 和调度资源。

所以现象是：导航栏先出来，中央 page 因首次冻结未解冻而显示空白；等事件循环处理完一批启动任务、数据回来或 timer 得到执行，才显示完整工作台。

**短期优化方案**

1. 工作台首屏不要走 BasePage 的首次冻结/淡入
   工作台内容在构造期已经创建，不需要通过冻结避免懒加载闪烁。建议给 **WorkspacePage** 单独禁用首显冻结，或在 BasePage 增加类似 **_freeze_on_first_show** 开关。这样启动后至少立即显示默认卡片/骨架，不再空白。
2. 首屏先绘制，再拉数据
   _setup_content() 只构建静态 UI，不立即 **_refresh_data()**。在 **showEvent()** 或主窗口 **show()** 后 **QTimer.singleShot(50~100ms, _refresh_data)**。这样第一帧不会和 DB 查询抢事件循环。
3. 媒体库统计延后
   媒体库视频/图片统计不是首屏最关键数据，建议启动后 800~1500ms 或首次空闲再刷新；有缓存时先显示缓存，没有缓存显示 **—**。不要和工作台基础统计同帧启动。
4. 避免重复刷新
   现在 **_setup_content()** 和 **showEvent()** 都会触发刷新，虽然 **_is_loading** 会挡住一部分，但媒体库刷新仍可能重复排队。统一由一个入口调度，带 debounce。

**中期优化方案**

1. 重写工作台统计为 SQL 聚合
   不要 **find_records(limit=10000)** 后 Python 聚合。新增 repository 方法：

   * 今日成功/失败/总数：**created_at >= today_start AND created_at < tomorrow_start GROUP BY status**
   * 近 14 天趋势：按日期和状态 **GROUP BY date(created_at), status**
   * 近 7 天成功率：只 count **success/failed**
   * 平台分布：账号表 **GROUP BY platform**
   * 待执行任务：保留当前 **count_records(status_in=["pending", "failed"])**

   这样工作台统计从“拉 10000 行 + Python 处理”变成“数据库返回几十行”。
2. **get_dashboard_data()** 并发化并复用账号列表
   当前是串行：

   `<span><span>account_stats = await ...</span> <span>publish_stats = await ...</span> <span>task_stats = await ...</span> <span>reminders = await ...</span></span>`

   应改为能并发的部分 **asyncio.gather()**，并把账号列表传给账号统计和最近发布提醒，避免重复查询账号表。
3. 为工作台加内存快照缓存
   页面创建时先使用最近一次 **DashboardSnapshot**，后台刷新后再更新 UI。后续从其他页面返回工作台也可以立即显示旧值，再静默刷新。
4. 图表组件延迟创建
   src/ui/components/charts.py 会导入 **PySide6.QtCharts** 并创建 **QChart/QChartView**。首屏可以先创建统计卡片和快捷入口，图表区下一帧或数据回来后再创建，减少首帧压力。

**更好的技术方案**

如果要彻底改善体验，建议把工作台改成“渐进式仪表盘”：

* 第一帧：只显示静态布局、欢迎语、默认/缓存统计卡片。
* 100ms 内：加载账号数、待执行任务这种轻查询。
* 300~800ms：加载发布趋势和最近发布。
* 1s 以后或空闲：加载媒体库统计、图表动画。
* 所有模块独立失败、独立 loading，不阻塞整个页面显示。

这样即使数据库大、媒体库目录大，用户也不会看到空白页。

**建议优先级**

P0：禁用工作台首次冻结 + 首屏后再刷新数据。
P1：媒体库统计延后，去掉启动期重复刷新。
P2：发布统计 SQL 聚合，避免 **limit=10000** 全量拉取。
P3：工作台快照缓存和图表延迟创建。

这几个改完后，启动体验应该从“导航栏先出、工作台空白 1-2 秒”变成“工作台立即可见，数据逐块刷新”。

### 闪退修复（2026-05-22）

`fatal_crash.log` 记录为 Qt 主线程 **ACCESS_VIOLATION**（非 Python 异常）。根因：`reveal_with_data` 在无遮罩时连续两次 `set_data(animate=True/False)`，且 `QTimer.singleShot` 未绑定父对象，页面切换后仍改 chart。

修复要点：

- reveal **只写入一次** series；有遮罩时等淡出后再写。
- reveal 定时器挂到 `ChartBase`，`cancel_pending_reveal()` 在 `hideEvent` / 管道取消时调用。
- 缓存首屏直接填图，**不做**入场动画（`animate_entry=False`）。
