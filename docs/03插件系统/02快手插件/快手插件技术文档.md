## 2. 步骤链组装逻辑

### 2.1 视频与图文使用不同步骤链

快手插件在 `publish_plugin.py` 中根据 `metadata["publish_type"]` **动态组装可执行步骤列表**；**进度阶段数恒为 11**（`StepRunner` 将连续的 `MusicSettingStep` + `AuthorServiceStep` 合并为同一阶段编号）。

| 发布类型 | 步骤 6（可执行子步骤） | 进度阶段总数 |
|---------|------------------------|-------------|
| 视频（`publish_type != "image"`） | 仅 `AuthorServiceStep`（6b） | **11** |
| 图文（`publish_type == "image"`） | `MusicSettingStep`（6a）→ `AuthorServiceStep`（6b），日志均为 `[步骤6/11 …]` | **11** |

```
【视频发布】11 个进度阶段（11 个可执行步骤）
步骤1   NavigateHomeStep        → 导航到快手创作者首页
步骤2   EnterPublishEntryStep   → 进入发布页
步骤3   UploadMediaStep         → 上传视频文件
步骤4   MetadataFillStep        → 填写正文和话题
步骤5   CoverSettingStep        → 封面设置（当前占位）
步骤6   AuthorServiceStep       → 作者服务/关联商品（条件执行）
步骤7   ManageHotspotStep       → 关联热点（占位）
步骤8   AuthorStatementStep     → 作者声明 / 作品申明（Ant Design Select）
步骤9   LocationStep            → 位置设置（占位）
步骤10  PublishSettingsStep     → 发布设置（定时发布）
步骤11  SubmitStep              → 提交发布

【图文发布】11 个进度阶段（12 个可执行步骤；阶段 6 含两个小步骤）
步骤1~5 同上
步骤6   MusicSettingStep        → 添加音乐（条件执行，图文专属），阶段号 6
        AuthorServiceStep       → 作者服务/关联商品（条件执行），阶段号仍为 6
步骤7~11 同上（与视频的阶段编号一致）
```

`publish_plugin.py` 核心组装代码：

```python
is_image = metadata.get("publish_type") == "image"

common_pre  = [NavigateHomeStep(), EnterPublishEntryStep(), UploadMediaStep(),
               MetadataFillStep(), CoverSettingStep()]
step6       = [MusicSettingStep(), AuthorServiceStep()] if is_image else [AuthorServiceStep()]
common_post = [ManageHotspotStep(), AuthorStatementStep(), LocationStep(),
               PublishSettingsStep(), SubmitStep()]
steps = common_pre + step6 + common_post
```

### 2.2 视频与图文的差异对照

| 步骤 | 视频场景 | 图文场景 | 差异说明 |
|------|---------|---------|---------|
| UploadMediaStep | 上传视频文件 | 上传图片文件（可多张） | 内部根据 `publish_type` 区分 |
| MusicSettingStep | **不在步骤链中** | 第 6 阶段内先执行，配置了 `music_random` 或 `music_keyword` 则执行 | 图文专属步骤 |
| AuthorServiceStep | 第 6 阶段 | 第 6 阶段内紧接 6a 后执行 | 均为条件执行；图文与视频进度号均为 6 |

### 2.3 占位步骤说明

以下步骤当前为占位实现，步骤体内仅记录日志后立即返回成功，不做任何 DOM 操作：

| 步骤 | 预期功能 | 当前状态 |
|------|---------|---------|
| CoverSettingStep | 封面设置 | 占位，直接返回成功 |
| ManageHotspotStep | 关联热点话题 | 占位，直接返回成功 |
| LocationStep | 位置/POI 信息填写 | 占位，直接返回成功 |

## 3. 各步骤详细说明

### step_01_home.py — NavigateHomeStep

**功能**：导航到快手创作者首页，确认登录状态。

**执行逻辑**：
- `goto` 默认 profile 页（`https://cp.kuaishou.com/profile`）
- 检测登录跳转和风控弹窗
- 确认当前域名在 `cp.kuaishou.com`

**成功判定**：URL 确认在创作者域名，无登录弹窗

---

### step_02_entry.py — EnterPublishEntryStep

**功能**：进入发布页面（视频或图文）。

**执行逻辑**：
- 图文发布：跳转 `https://cp.kuaishou.com/article/publish/video?tabType=2`，等待图文 Tab 特征元素
- 视频发布：跳转 `https://cp.kuaishou.com/article/publish/video`，等待视频上传区域
- 确认未掉登录状态

**成功判定**：发布页特征元素可见

---

### step_03_upload.py — UploadMediaStep

**功能**：上传媒体文件（视频或图片）。

**执行逻辑**：
- 对隐藏的 `input[type=file]` 调用 `set_input_files` 传入文件路径
- 图片上传：使用 `IMAGE_FILE_INPUT`（`accept*='image'`）选择器，支持一次传多张
- 轮询 `UPLOAD_SUCCESS_MARKER` 直到上传完成，超时约 180 秒

**关键选择器**：`FILE_INPUT` / `IMAGE_FILE_INPUT`、`UPLOAD_SUCCESS_MARKER` / `IMAGE_UPLOAD_SUCCESS_MARKER`

**成功判定**：上传成功标志元素可见

---

### step_04_description.py — MetadataFillStep

**功能**：填写正文内容和话题标签。

**执行逻辑**：
- 目标区域：`#work-description-edit`（富文本编辑器，DOM 报告稳定 ID）
- 正文与话题分离：先从 `description` 去掉 `#话题` 得到纯正文，再合并 `tags`（最多 4 个、去重）
- 正文用 `desc_box.type` 写入；每个话题分两阶段：
  1. **触发话题编辑态**（须出现 `[class*='_dropdown-container_']` 或 `_topic-item_`，否则禁止输入词名）：优先 CDP 真按键 `#`（Shift+3），失败则点「# 智能话题」按钮
  2. **词名 + 收成**：`page.keyboard.type` 输入完整词名后按 **空格** 收成（不点击话题下拉）；成功标准为 `.at-tag-item` 数量较本话题前 +1
- 触发失败会 Backspace 清理末尾裸 `#`，并写 `%LOCALAPPDATA%\WeMediaBaby\debug\kuaishou\topic_trigger\` 截图
- 输入前先关闭可能出现的引导提示

**关键字段**：`metadata["description"]`、`metadata["tags"]`

**平台限制**：最多 4 个话题

### step_06a_music.py — MusicSettingStep（图文专属）

**功能**：为图文内容添加背景音乐（条件执行）。

**触发条件**：
- `metadata["music_random"] = True` → 从推荐列表随机选一首
- `metadata["music_keyword"]` 有值 → 搜索后从结果中随机选一首
- 两者均未配置 → 直接跳过

**执行逻辑**（基于 DOM 分析报告 20260403）：
1. 检查「更换音乐」是否已出现，若是则跳过（幂等）
2. 点击「添加音乐」按钮（文案定位，ref=e1236），等待「选择音乐」抽屉出现（8 秒）
3. 定位抽屉内容作用域（优先 `_music-drawer_` class，兜底退回整页）
4. 若有关键词，在搜索框（`placeholder=搜索音乐`）输入，等待结果稳定 2.5 秒
5. 收集列表内可见曲目行（3 层策略，见下），随机选一条
6. `hover(force=True)` 到选中行，等待 800ms，点击行内或抽屉内最后一个可见的「添加」
7. 按 Escape 收起抽屉，验证「更换音乐」出现（8 秒）

**曲目行收集策略（按优先级）**：
1. `class*='music-item'` 等 class 关键词（DOM 报告命名）
2. `div:has(img)` + 文案含 `mm:ss` 时长（快手每条曲目必有封面图）
3. XPath 找时长节点（≤5 字符含冒号），上溯 2 层取行容器

**成功判定**：「更换音乐」按钮可见，或 `class*='music-info'` 区域存在

**失败处理**：关键步骤失败返回 `PublishResult(success=False)` 终止发布

**关键 DOM 参考**（报告 20260403）：
- 添加音乐按钮：文案「添加音乐」，ref=e1236
- 抽屉标题：「选择音乐」，ref=e285
- 搜索框：placeholder=「搜索音乐」，ref=e1240
- 音乐列表容器：class 含 `music-list`，ref=e1243
- 音乐项：class 含 `music-item`，hover 后右侧出现「添加」按钮，ref=e1678
- 成功标志：「更换音乐」，ref=e1690

### step_06b_author_service.py — AuthorServiceStep

**功能**：关联商品（快手购物车/作者服务）挂载（条件执行）。

**触发条件**：`metadata["kuaishou_goods_name"]` 有值时执行；否则直接跳过。

**执行逻辑**（主文档内，无 iframe/Shadow DOM）：
1. 点击「选择服务类型」combobox，展开服务类型菜单（5 秒）
2. 选择「关联商品」选项，等待商品输入框从 disabled 变为 enabled（6 秒）
3. 点击「关联商品获得更多收入」combobox，激活商品搜索
4. 输入商品名称，等待即时过滤完成（2.5 秒）
5. 点击第一个商品选项，完成挂载（6 秒）
6. 验证 combobox 收起后显示已选商品名称（3 秒）

**成功判定**：combobox 显示已选商品名（collapsed 状态）

**失败处理**：任一关键步骤失败，返回 `PublishResult(success=False)` 终止发布

### step_10_settings.py — PublishSettingsStep

**功能**：发布时间设置（定时/立即）。

## 4. StepRunner 执行引擎

位于 `steps/step_runner.py`，继承通用 `GenericStepRunner`。

**核心特性**：
- **动态进度编号**：`run()` 开始时调用 `_build_kuaishou_phase_groups()`：将连续的 `MusicSettingStep`+`AuthorServiceStep` 合并为同一阶段，重建 `_phase_index` 与 `_total_phases=11`，视频与图文均显示「步骤X/11」；6a/6b 两条日志同为「步骤6/11 …」
- **顺序执行**：步骤按列表顺序逐一执行
- **步骤重试**：每步最多 3 次，失败间隔 1.5 秒（上传步骤用指数退避）
- **NeedsAction 补救**：`need_supplement` 映射 → 重新执行 `[SubmitStep()]`
- **防风控**：`step_interval`、`optional_browse_before_action`

```python
runner = StepRunner(
    page=page,
    file_path=file_path,
    metadata=metadata,
    config=RunnerConfig(
        max_step_retries=3,
        step_retry_delay_seconds=1.5,
        max_submit_retries=2,
    ),
    action_handlers={"need_supplement": lambda: [SubmitStep()]},
)
result = await runner.run(steps)  # steps 为动态组装后的列表
```

失败时由 `GenericStepRunner._diagnose()` 生成诊断包（`platform=kuaishou`），详见 §9。

## 5. 登录插件

登录检测采用双重验证机制：

| 验证方式 | 说明 |
|---------|------|
| Cookie 脚本检测 | 注入 JavaScript，检查 document.cookie 中的登录态 |
| HTTP 验证（`verify_cookie_http`） | 请求 profile 接口，检查响应码（200 为已登录，302 为未登录） |

`extract_user_info`：解析登录用户信息（昵称、UID 等），用于账号管理页展示。

## 6. 表单字段（FormSchema）

| 字段名 | 类型 | 必填 | 说明 |

| `music_keyword` | text | 否 | 图文音乐搜索关键词（搜索后随机选一首） |
| `scheduled_publish_time` | datetime | 否 | 定时发布时间 |
| `schedule_time` | datetime | 否 | 同上（兼容字段名） |

## 9. 发布失败诊断

通用机制见 [3.1 第 5.5 节](../3.1插件系统标准化目录及结构.md)、[3.2 第 6.1 节](../3.2插件选择器标准化规范.md)。

## 10. 常见故障排查

| 现象 | 可能原因 | 排查方式 |
|------|---------|---------|
| 话题重复写入 | 描述框中已有话题，`MetadataFillStep` 未清空 | 检查输入前是否先清空编辑器 |
| 发布按钮点击无响应 | 发布页面存在遮挡层 | 查看 `SubmitStep` 关闭浮层逻辑 |
| 定时发布时间未生效 | DatePicker 交互异常 | 确认使用 `mouse.click` 而非 `locator.click` |
| 上传超时 | 文件过大或网络不稳定 | 调整 `UploadMediaStep` 超时配置 |
| 商品挂载失败 | 快手后台页面结构变化 | 检查 `AuthorServiceStep` 选择器，对照最新 DOM |
| 音乐步骤找不到列表 | 快手音乐弹窗 class 名变化 | 查看 `step_06a_music.py` 日志，确认哪条策略命中，对照新 DOM 更新选择器 |
| 进度编号错误 | 阶段合并逻辑与步骤链不一致 | `StepRunner.run()` 通过 `_build_kuaishou_phase_groups()` 合并 6a+6b，固定 `_total_phases=11` |
