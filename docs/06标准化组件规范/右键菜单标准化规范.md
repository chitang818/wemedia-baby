## 1. 概述

为保持各列表页、表格区域上下文菜单在**视觉风格、交互节奏、异步反馈**上的一致性，制定本规范。  
**参考实现**：账号管理页（`AccountTableWidget` → `AccountPage._on_context_menu` → `AccountContextMenu`）。

与《[弹窗组件标准化规范](./弹窗组件标准化规范.md)》的关系：右键菜单负责「就地唤起操作」；需要二次确认或复杂表单时，菜单项触发后应打开标准弹窗，而不是在菜单内堆叠 UI。

---

## 2. 技术选型

| 场景 | 推荐组件 | 说明 |
|------|----------|------|
| 主路径（已安装 qfluentwidgets） | `RoundMenu` + `Action` + `FluentIcon` | 与主窗口 Fluent 主题一致，圆角、悬停、图标尺寸统一 |
| 降级（库不可用或极简场景） | `QMenu` + `QAction` | 文案与主路径**完全一致**（含词条统一，如「刷新登录状态」勿写「同步状态」）；图标尽量 `FluentIcon.*.icon()` |
| 共用工具 | `src/ui/components/fluent_context_menu.py` | `round_menu_parent(widget)`、`is_round_menu_alive(menu)`、`install_round_menu_close_on_app_inactive(menu)`，避免各页重复实现 |
| 不推荐 | 在业务页内每次 `exec` 前 `new` 整棵菜单且含大量控件 | 易造成右键卡顿，见第 6 节性能要求 |

## 3. 视觉与布局规范

### 3.1 菜单容器

- 使用 `RoundMenu(parent=主窗口)`，**父级优先取 `round_menu_parent(业务控件)`**（即 `widget.window()`），避免菜单挂在内嵌控件上时出现主题/阴影渲染异常（见 `AccountContextMenu._init_fluent_menu`）。
- 不通过全局 `style.qss` 强行覆盖 Fluent 菜单内部结构；主题跟随应用与 `qfluentwidgets` 的明暗色配置。

### 3.2 菜单项（Action）

- **文案**：全部使用简体中文，与界面其他按钮用语一致（例如「刷新登录状态」而非「同步状态」；「移动至分组」与 Fluent 主路径一致）。
- **图标**：每个常用项配 `FluentIcon`，语义清晰（打开/复制/同步/删除等）。库中无专用图标时可用最接近语义图标（如指纹可用 `FINGERPRINT` 或回退 `SEARCH`）。
- **顺序（建议）**  
  1. 高频、低风险：打开、复制等  
  2. 分隔线  
  3. 数据变更类：更新、刷新状态、移动分组等  
  4. 分隔线  
  5. 查看类：查看环境指纹等  
  6. 分隔线  
  7. **破坏性操作置底**：删除（单独一组，上方加分隔线）

### 3.3 分隔线

- 用 `addSeparator()` 区分「导航/信息类」「维护类」「危险操作」，避免一长串平铺。
- 分隔线不宜超过 3 段，否则考虑收拢为二级菜单或独立入口。
- **复用固定结构的 RoundMenu** 时，若某一项需隐藏且隐藏后会出现「孤立分隔线」，可改为该项 **`setEnabled(False)` + `setToolTip` 说明原因**（见发布列表页「重新发布」在无失败任务时的处理），而不是 `setVisible(False)`。

### 3.4 动态显隐

- 某回调不存在时，对应项应 `setVisible(False)`（账号表：`AccountContextMenu._sync_action_visibility` 按 `callable(callbacks[key])` 判断）。
- 与选择范围相关的项：在 `show_menu` / `exec` 前更新可见性或启用状态。
- 菜单项文案可按选中数量动态 `setText`（如「删除选中记录（3 条）」），**不必**为每种文案重建菜单。

## 4. 与列表/表格的集成

### 4.1 策略与坐标

- 表格设置：`setContextMenuPolicy(Qt.CustomContextMenu)`，连接 `customContextMenuRequested`。
- **坐标**：使用 `table.viewport().mapToGlobal(pos)` 再 `exec`，保证菜单位置与点击单元格对齐。
- **选中与右键目标一致**：在弹出菜单前对右键所在行执行 `selectRow`（或等价多选策略），并用 `selectionModel().blockSignals(True/False)` 包裹，避免多余副作用；**账号管理表、批量预览表、发布记录/列表表**均已按此处理。

### 4.2 信号与解耦

- 表格组件只负责解析当前行数据并 `emit` 信号（如 `context_menu_requested`），**不直接依赖业务服务**（账号表）。
- 页面层组装 `callbacks` 字典，菜单管理器只负责展示与分发；或页面内 `_ensure_*_round_menu` + `triggered` 槽读取 `_pending_rows` / `_list_ctx_failed_records` 等**仅用于当次打开的上下文**（发布记录/列表表）。

### 4.3 空白区域

- 点击空白处不弹出菜单；若需「表格空白处粘贴/新建」等，单独产品设计，不在本规范默认范围内。

### 4.4 应用失焦时关闭 RoundMenu（必做）

- **背景**：`qfluentwidgets.RoundMenu.exec` 内部主要是 `show()` 出 `Qt.Popup`，并非阻塞式 `QMenu.exec` 模态循环；用户未点选菜单项即 **Alt-Tab / 任务栏切换到其他应用** 时，弹层在 Windows 上可能仍浮在最前，盖住其他程序窗口。
- **要求**：每个复用的 `RoundMenu` 实例在**创建完成后**（`addAction` 等装配结束之后）调用一次  
  `install_round_menu_close_on_app_inactive(menu)`。  
  该工具会监听 `QApplication.applicationStateChanged`，在非 `ApplicationActive` 时若菜单仍可见则 `close()`；菜单 `destroyed` 时自动断开连接，避免泄漏。
- **已对齐页面**：账号库 `AccountContextMenu`、发布列表 / 发布记录表、素材视频库表、批量预览表（`batch_preview_context_menu`）。新增页面凡使用 `RoundMenu` 主路径，须同样调用。

## 5. 加载与异步反馈规范

右键菜单通常在用户点击某项后关闭（`exec` 返回），**菜单本身不放长时间转圈**，长耗时操作的反馈放在菜单之外。

### 5.1 原则

| 操作耗时 | 推荐反馈 | 说明 |
|----------|----------|------|
| 极短（小于约 300ms） | 可无额外反馈，或仅日志 | 避免闪烁 |
| 批量、可计量进度 | `QProgressDialog`（模态）+ 取消若可取消 | 与账号页「同步账号状态」一致：`setMinimumDuration(0)`、`canceled` 连接取消逻辑 |
| 单条但需网络/验证 | 进度弹窗或行内状态更新 + 结束 `InfoBar`/轻提示 | 账号页单账号验证可走与批量同一套验证服务，结束时针对单账号文案提示 |
| 静默后台 | 不弹窗，列表/EventBus 更新 | 如「静默刷新」场景 |

### 5.2 禁止与建议

- **禁止**：在 `RoundMenu` 内嵌 `QProgressBar` 或阻塞 UI 线程的网络请求。
- **建议**：操作开始前关闭菜单（默认即如此）；异步任务使用项目现有 `async_helper` / 服务层回调，在页面层统一接 `verification_started` / `progress` / `finished` 等信号。
- **可选增强**：在触发后到弹窗出现前极短空档，可在工具栏或表格行显示 `IndeterminateProgressRing`（与 qfluentwidgets 其他页一致），避免「点了没反应」的错觉；需与视觉规范统一尺寸与位置。

### 5.3 错误与成功提示

- 失败：使用项目统一的 `fluent_dialogs` 或 `InfoBar`（与弹窗规范一致），文案说明可操作下一步。
- 成功：短文案即可；批量操作给汇总，单条操作给针对性结果（账号页单账号验证即为例）。

## 6. 性能与生命周期

- **复用菜单实例**：在页面 `_setup_content` 或等价时机**预创建**菜单管理器 / `RoundMenu`，`exec` 前只更新上下文、`setText`、可见性/启用状态；避免首次右键才创建整表菜单（账号页：`AccountContextMenu` 在 `AccountPage._setup_content` 中构造）。
- **预创建 Action**：与 `RoundMenu` 一并创建，`triggered` 连接固定槽，槽内读取「当次打开」写入的上下文（账号表、发布记录/列表表、批量预览表）。
- **主窗口销毁 / 对象失效**：`exec` 前用 `is_round_menu_alive(self._menu)` 检测；失效则清空引用并重新 `_init`（账号表：`AccountContextMenu._ensure_fluent_menu`）；重建后的新 `RoundMenu` 须再次调用 `install_round_menu_close_on_app_inactive`（与首次创建时相同，在 `_init` 末尾调用即可）。
- **降级路径**：`QMenu` 可每次新建（仅作 fallback），文案、词条与主路径一致；标准 `QMenu.exec` 为阻塞模态，一般不受上述「失焦残留最前」问题影响，无需挂载失焦关闭逻辑。

## 7. 实现检查清单（Copy-paste）

新页面或重构时自查：

- [ ] 主路径为 `RoundMenu` + `Action`，`parent` 为 `round_menu_parent(页面或表格)`  
- [ ] 所有菜单文案为简体中文，词条与同类页面、Fluent/降级两路径一致  
- [ ] 图标语义正确，危险操作在最后一组并有分隔线  
- [ ] 表格使用 `viewport().mapToGlobal`；右键行与 `selectRow` 一致（必要时 `blockSignals`）  
- [ ] 异步操作不在菜单内阻塞；进度/完成有明确反馈  
- [ ] 提供 `qfluentwidgets` 不可用时的 `QMenu` 降级，且回调键/行为一致  
- [ ] 可选菜单项按上下文显隐或置灰+`toolTip`，无「死项」  
- [ ] 失效 `RoundMenu` 可自动重建  
- [ ] `RoundMenu` 创建后已调用 `install_round_menu_close_on_app_inactive(menu)`（见 §4.4）
